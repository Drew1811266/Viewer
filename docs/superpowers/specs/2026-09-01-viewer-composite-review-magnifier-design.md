# Viewer 复合评审放大镜设计

> Status: Selected design — awaiting written review
>
> 日期：2026-09-01
>
> 类型：图片评审工作台与放大镜渲染边界优化

## 1. 背景与根因

图片评审工作台目前把放大镜与评审标注作为两套独立渲染系统：

- `ImageMagnifier` 只复制并变换原图；
- `AnnotationCanvas` 和编号标记在独立的舞台覆盖层中渲染；
- 放大镜位置算法只知道鼠标位置、舞台尺寸和镜片尺寸，不知道评审几何；
- 标注层位于放大镜上方，因此镜片经过选区时，未放大的选区和编号会浮在已经放大的图片内容上。

这不是简单的层级或避让问题。图片内容与评审框来自不同投影，导致同一个屏幕区域同时表达两种比例，破坏了评审位置的视觉真实性。

## 2. 已确认的产品决策

采用“图片与评审标注组成复合观察层”的方案：放大镜观察图片时，同时观察与该图片绑定的评审框、画笔轨迹和编号标记。

不采用“镜片边缘遇到评审框后动态裁掉相交区域”的方案。动态裁剪会让镜片在多条意见之间频繁变形或碎裂，也可能裁掉用户正在检查的焦点区域，难以形成稳定、可预测的生产力工具交互。

## 3. 交互与视觉契约

### 3.1 镜片内外的一致关系

- 鼠标指向的源图像素继续是放大镜的精确采样中心；镜片位置偏移不能改变采样点。
- 矩形选区、画笔轨迹和正在绘制／调整的临时几何与图片使用同一个源图坐标变换。
- 镜片内的标注位置和形状随图片同步平移、旋转和缩放，不出现舞台比例标注浮在放大图片上的情况。
- 镜片外继续显示现有评审标注；镜片本身是不透明的复合表面，覆盖其下方的普通标注，再在内部绘制正确比例的标注副本，避免双重显示。
- 整图意见没有图片几何，不在镜片内伪造标记。

### 3.2 线条与编号

- 选区和画笔的几何尺寸随倍率放大。
- 轮廓线宽随倍率增长但限制在 2–5 CSS px，避免高倍率下遮住被评审细节。
- 意见编号跟随其规范化锚点投影到镜片内部，但保持固定的可读尺寸，不随倍率膨胀。
- 选中、草稿和保存状态沿用现有颜色、虚线和高对比语义；本轮不增加新的标注外观设置。
- 调整矩形的交互手柄不复制进镜片。镜片中的内容只负责观察，实际手柄继续由舞台标注层持有。

### 3.3 输入所有权

- 放大镜保持 `pointer-events: none`，不抢占标记选择、矩形移动／缩放、画笔绘制、拖拽平移或文字输入。
- 放大镜启用后，即使标注画布为阻止冒泡而持有绘制手势，预览舞台仍在捕获阶段记录指针采样，镜片可以连续跟随并显示实时草稿。
- 浏览、旋转、缩放、平移、切换图片、改变镜片形状／面积／倍率时，图片与镜片内标注必须在同一个动画帧使用同一份变换快照。
- Q 键、工具栏开关、镜片启用生命周期和离开真实图片像素后隐藏的现有行为保持不变。

## 4. 架构设计

### 4.1 保持通用预览与评审领域隔离

`ImagePreviewSurface` 和 `ImageMagnifier` 仍是通用图片预览组件，不导入评审 Controller、Feedback DTO 或持久化协议。

通用层只新增一个窄的可选绘制端口：

```text
MagnifierOverlayPainter.paint(context, magnifierProjection)
```

其中 `magnifierProjection` 只包含：

- 镜片逻辑尺寸和设备像素比；
- 原图尺寸；
- 当前源图采样点；
- 当前图片显示比例与放大镜倍率；
- 当前旋转角度；
- `normalizedToLens(point)` 的纯坐标映射。

普通图片预览不提供 Painter，仍只显示原图。图片评审工作台在组合层把当前标注场景转换为 Painter 后注入，避免通用预览反向依赖评审领域。

### 4.2 共享标注场景

从 `AnnotationCanvas` 中抽取只读的规范化标注场景与纯绘制函数。场景包含：

- 已保存的 `image_rect` 和 `image_stroke`；
- 每条意见的稳定 Item ID 和当前快照编号；
- 当前选中状态；
- 正在创建、重绘或调整的临时 Anchor；
- 保存、草稿、选中等显示状态。

舞台标注画布与镜片标注画布消费同一场景，不各自解释 Controller 状态。交互按钮和矩形手柄仍只在 `AnnotationCanvas` 的 DOM 层渲染。

### 4.3 镜片投影

镜片坐标映射使用单一纯函数：

```text
normalized source point
  → original source pixel
  → delta from sampled source point
  → current rotation
  → preview scale × magnifier factor
  → lens-local point
```

该映射与放大镜原图使用的 CSS 变换共享同一份计算结果，禁止分别推导比例或旋转方向。0°、90°、180°、270° 都必须保持图片与标注重合。

现有镜片外壳定位算法继续负责靠近鼠标、边缘翻转和舞台内约束；它不再承担评审标注避让，因为镜片内容本身已经可以正确显示标注。

### 4.4 镜片渲染

镜片内部增加一个与镜片等大的高 DPI Canvas：

- Canvas 只分配镜片大小，不创建与 6K／8K 原图同尺寸的标注缓冲区；
- 原图继续使用现有 `<img>` 和安全原图加载管线；
- 标注 Canvas 位于镜片原图上方，与原图一起被镜片边界裁切；
- 编号使用镜片局部坐标直接绘制，保持固定屏幕尺寸；
- 放大镜整体层级高于普通标注层、低于文字编辑器和阻塞对话框。

位置、图像 CSS 变量和标注 Canvas 在同一个 `requestAnimationFrame` 中刷新，避免镜片移动时出现一帧图像已更新、标注仍滞后的撕裂。

### 4.5 数据流

```text
Review Controller snapshot
  → buildAnnotationScene（规范化、只读）
  ├─→ AnnotationCanvas（舞台投影 + 可交互标记／手柄）
  └─→ MagnifierOverlayPainter
        → MagnifierProjection（镜片投影）
        → 镜片内非交互标注 Canvas
```

放大镜不会复制、修改或持久化评审数据。Agent 读取的 Feedback、Anchor、revision 和存档协议完全不受本次显示优化影响。

## 5. 性能、失败与可访问性

- 指针事件只更新 Ref，图像与标注绘制继续按动画帧合并，不因每次移动触发 React Render。
- 镜片 Canvas 的物理分辨率按设备像素比生成，并将倍率限制在现有安全范围；窗口或设备像素比变化后重新配置。
- 画笔路径继续遵守现有 2,048 点上限；只有镜片可见时才绘制镜片标注。
- Painter 或 Canvas Context 不可用时，放大镜退化为仅显示原图，不影响图片预览、标注编辑或评审数据。
- 镜片保持非交互、`aria-hidden`；现有“放大镜已开启／关闭”播报不变。标注的可访问名称和键盘操作仍由普通舞台层负责。
- 强制颜色、高对比和减少动态效果沿用现有 Viewer 设计令牌与行为。

## 6. 非目标

本轮不包含：

- 修改放大镜面积、形状、倍率选项或默认值；
- 基于意见密度自动移动、缩小或裁切镜片；
- 在镜片内部直接点击、编辑或拖动标注；
- 修改 Anchor、Feedback、存档、历史或 Agent 读取协议；
- 视频时间点／时间段标注的放大观察；
- AI 自动识别问题或修改素材；
- 代码签名、Apple 公证、正式安装包、上架或发售。Viewer 仍处于开发初期，这些事项不是本轮计划、验收或收尾任务。

## 7. 测试与验收

实施必须按红绿重构完成以下覆盖：

1. 纯几何测试验证四个旋转角度、不同倍率和不同源图比例下，图片采样点与标注投影重合；
2. 矩形、画笔、编号、选中项和实时草稿都能进入镜片场景，整图意见被排除；
3. 镜片内部线宽受限、编号保持固定尺寸；
4. 镜片启用时，绘制与调整手势仍由原标注层拥有，镜片持续跟随且不拦截指针；
5. 普通图片预览没有 Painter 时保持现有放大镜行为；
6. 原图加载中、加载失败、安全预算失败和导航切换不会显示上一张图片的标注；
7. 高 DPI、适应窗口、自由缩放、平移和旋转后不出现图像／标注错位；
8. 视觉验收场景包含镜片跨越矩形、画笔和多个编号的画面，确认镜片内部只显示一份正确比例的复合内容；
9. 完整 UI 测试、类型检查、静态检查和生产构建通过。

## 8. 预计代码边界

- `imagePreview/magnifierGeometry.ts`：新增镜片内容投影的纯几何；
- `imagePreview/ImageMagnifier.tsx`：统一帧刷新并托管镜片标注 Canvas；
- `imagePreview/ImagePreviewSurface.tsx`：新增可选 Painter 端口和捕获阶段指针采样；
- `review/annotationScene.ts`：规范化场景和共享几何绘制；
- `review/AnnotationCanvas.tsx`：复用共享场景，保留交互层职责；
- `review/ImageReviewWorkspace.tsx`：在组合层注入评审 Painter；
- 对应单元、组件、集成和视觉验收测试。
