# ADR 0001: macOS image pipeline backend policy

> Status: Active

> **Historical governance note (2026-07-23):** References to M4 or Viewer 0.1 release acceptance below describe the plan at the time this evidence was recorded. ADR 0005 cancelled M4 and replaced release acceptance with continuous development governance. The measured evidence in this document is unchanged.

- Status: Accepted
- Date: 2026-07-16
- Gate: G1 image pipeline prototype
- Reproduce: `./scripts/run-g1-image-gate.sh`

## Context

Viewer must browse hundreds of local JPG/PNG files without copying project originals into application storage. Grid thumbnails and high-resolution previews must preserve EXIF orientation, alpha and ICC/Display P3 color, stay cancellable, remain below the 700 MB short-peak budget and never send image bytes through JSON/Base64 IPC.

The architecture proposed two public macOS frameworks for grid thumbnails:

1. Quick Look Thumbnailing as the primary system thumbnail service, with Image I/O fallback.
2. Image I/O for every JPG/PNG thumbnail if the two paths differ visibly or Quick Look is unstable.

Fit previews and permitted 100% representations use Image I/O directly from the original file URL in both alternatives.

## Decision

**Quick Look primary, Image I/O fallback.**

- Grid thumbnails request a raw, undecorated Quick Look representation at the required physical-pixel size.
- A Quick Look error, timeout or rejected result falls back to Image I/O using a separate artifact path.
- Fit previews and budget-approved 100% representations always use Image I/O.
- Both paths transform EXIF orientation and encode the generated session representation as PNG.
- Project originals remain in place. Viewer stores only rebuildable session representations and exposes them through an opaque, session-bound `viewer-image` token.
- A session cancellation marks publication invalid before invoking the native Quick Look cancellation API; a completed stale result is deleted rather than published.

Every measured grid request used Quick Look; the separately injected failure test proved that the coordinator publishes the Image I/O fallback instead. The pixel gate converts each backend output through the appropriate sRGB or Display P3 Core Graphics context before comparison.

## Limitations and follow-up

The generated corpus is redistribution-safe and deterministic, but its valid images are only 640×480 to 1024×768. It proves API behavior, cancellation, color/orientation equivalence and the prototype resource envelope; it does not replace final performance acceptance with the user's approximately 10 MB images or a several-hundred-image project.

When the user supplies the standard test folder, M4 must rerun the preview, steady-memory and short-peak gates. Viewer will switch JPG/PNG grid thumbnails to Image I/O if that corpus reveals a visible color/orientation jump, Quick Look instability or a resource regression. No such issue was found in G1.

## Consequences

- Viewer keeps the lower-latency system thumbnail path without coupling domain/application code to Quick Look objects.
- Quick Look remains isolated on a dedicated executor because its generator and requests are not treated as general `Send`/`Sync` application state.
- Image I/O is still mandatory for deterministic fallback, metadata probes, fit previews and permitted 100% rendering.
- Session cache keys include source size, nanosecond mtime, representation parameters and renderer version; WebView URLs contain neither those keys nor filesystem paths.
- The custom protocol buffers encoded representation bytes outside JSON IPC. Decode concurrency and memory-pressure scheduling remain later milestone responsibilities.
