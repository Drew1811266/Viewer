# Viewer 测试启动链路与质量门禁架构优化计划

> 状态：已完成
> 日期：2026-09-09

## 目标

在不新增产品功能、不改变用户可见行为、也不引入签名/公证/正式安装包/上架任务的前提下，
让本地开发启动和自动化验收始终绑定当前工作树的真实 Viewer 进程，并修复运行时路径、质量
门禁和架构规模债务。

## 阶段

### 阶段 1：受管控的开发会话

- 为每次启动生成工作树绑定的会话清单，记录启动进程组、工作树和真实 Viewer 可执行文件；固定
  的 Vite 端口与验收窗口配置由受控入口显式提供。
- 为 Vite/Tauri 使用独立 loopback 端口并启用 strict-port；未知端口占用时失败，不连接旧前端。
- 只清理仓库范围内的开发进程组；打包版只用于冲突检测，绝不停止，也拒绝将其作为测试目标。
- 为 native acceptance 提供受管控启动入口，测试直接使用会话清单中的 PID/窗口，不按应用名称
  二次启动。
- 先运行启动门禁，再运行场景测试，最后运行全量质量门禁。

### 阶段 2：评审会话初始化稳定性

- 保留现有用户界面状态和错误文案，仅将桌面会话初始化整理为可观测的 single-flight 生命周期。
- 对初始化 worker 失败保留可诊断原因，并确保同一会话不会因并发首次读取反复初始化。
- 增加冷启动、热重载、重复打开和首次进入预览的回归测试。

### 阶段 3：质量与模块边界

- 为原生渲染适配器、viewport、magnifier 和 Rust actor 补齐测试覆盖，不降低现有覆盖率基线。
- 将最高风险的超大生产文件拆分到职责明确的模块，保持公开接口不变。
- 统一开发/构建视频运行时路径；开发构建不触发发布签名检查，构建缺失时给出确定性错误。
- 重新运行 UI、Rust、安全、架构趋势、原生和视觉验收。

## 不变量

- Viewer 产品 IPC、评审数据协议、用户可见交互和默认预览行为保持不变。
- 任何测试失败都保留日志和进程诊断，不继续使用未验证的窗口。
- 不修改用户项目、真实素材或 `.viewer` 数据；测试写入一次性夹具。
- 不把发布签名、公证、正式安装包、上架或发售列为本轮任务。

## 验收标准

1. 连续两次启动只留下一个当前工作树 Viewer，且会话清单中的 PID、路径和窗口所有权一致。
2. 任意未知进程占用开发端口时启动明确失败，不显示旧前端。
3. native acceptance 不调用应用名或 Bundle 启动，只连接启动器返回的 PID。
4. `pnpm quality`、`pnpm verify`、原生启动预检和自动化验收通过；`pnpm quality:report` 仅作为
   可选趋势证据运行，不进入交付阻断。若原生渲染迁移导致历史覆盖率基线暂时下降，必须记录
   具体模块和原因，不得通过刷新基线或宽泛豁免掩盖。
5. `pnpm tauri build --debug` 在运行时路径完整时能进入正常构建流程；缺失运行时时失败信息明确，
   且不会要求发布签名身份。
