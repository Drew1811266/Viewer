# Viewer 适窗倍率、原图预览与放大镜联动修订设计

**日期：** 2026-08-07  
**状态：** 已批准  
**范围：** 单图预览的显示基准、原图渐进加载、MacBook 触控板缩放，以及指针旁放大镜的倍率与动画

**修订关系：** 本文覆盖
`2026-08-06-viewer-trackpad-zoom-and-image-magnifier-design.md` 中关于单图预览
“原始像素 100%”、自由缩放长期使用适窗代理、放大镜独立于主图倍率，以及旧显隐动画的定义。
Q 键所有权、指针旁放置、设置值、解码安全预算和未被本文修改的其他约束继续有效。

## 1. 背景与问题

当前单图预览同时存在“适应窗口”和“原始像素 100%”两套显示基准，但工具栏在两种模式下都会显示 `100%`。默认适窗模式最终长期显示最长边不超过 2400 px 的 `fit_preview`，只有点击旧的 100% 按钮或开启放大镜时才请求 `original100_percent`。

这一模型带来三个相互关联的问题：

1. 用户无法从百分比判断当前图像相对于窗口的实际大小；
2. 放大镜直接把原图像素按 1.5/2/3 倍绘制，未包含主图适窗比例，导致镜内外视觉倍率突变；
3. 触控板捏合的系数偏低，真实 MacBook 上缩放不够灵敏，现有自动测试只验证事件契约，没有验证实机手感。

现有放大镜显隐仅在 110–140 ms 内从 85% 过渡到 100%，弹出和收回也不够明显。

## 2. 已批准的产品决策

### 2.1 唯一倍率基准

- “适应窗口”是唯一的 `100%` 基准。
- 删除独立的、可点击的“原始像素 100%”模式按钮。
- 工具栏显示顺序改为 `适应窗口｜−｜百分比｜+`。
- 百分比始终表示当前显示尺寸相对于适窗尺寸的比例；它不表示 CSS 像素与原图像素的一比一关系。
- 点击“适应窗口”会把图像完整居中显示、清除平移并回到 `100%`。
- 缩放范围保持 `10%–800%`，工具栏缩放按钮继续使用稳定的乘法档位。
- 旋转后依据旋转方向重新计算适窗尺寸。窗口变化时，适窗状态继续保持 `100%`；自由缩放状态保留相对倍率并重新夹取平移边界。

### 2.2 原图作为最终显示表示

- 当前图片最终使用方向修正后的 `original100_percent` 表示，不再长期停留在适窗代理。
- `fit_preview` 仍可作为打开图片时的快速占位，以及原图超出安全预算或加载失败时的回退。
- 代理和原图必须使用同一套原图尺寸元数据计算几何。原图就绪后在相同位置和显示尺寸无跳动替换代理。
- 替换不得重置缩放、平移、旋转、放大镜开关或鼠标下的采样位置。

### 2.3 放大镜倍率语义

- 设置中的 `1.5× / 2× / 3×` 表示相对于鼠标下当前可见图像的额外倍率。
- 镜内的最终显示比例等于 `当前主图显示比例 × 放大镜倍率`。
- 例如主图处于适窗 `100%`、放大镜为 `1.5×` 时，镜内为适窗基准的 `150%`；主图处于 `200%` 时，镜内为 `300%`。
- 放大镜始终使用原图表示进行采样，不能放大适窗代理并将其呈现为原图细节。
- 放大镜复用主图已加载的当前原图，不发送第二次原图请求，也不保留另一份解码副本。

## 3. 交互设计

### 3.1 工具栏与视口

单图预览工具栏移除旧的 `按 100% 显示` 按钮，保留：

1. `适应窗口`：重置到适窗基准；
2. `缩小`：围绕舞台中心按既有乘法档位缩小；
3. 只读百分比：四舍五入显示当前相对适窗倍率；
4. `放大`：围绕舞台中心按既有乘法档位放大。

适窗状态下，“适应窗口”显示激活状态。任何触控板捏合或加减按钮操作都会进入自由缩放，但只要结果被重置到适窗状态，就恢复 `100%` 和激活状态。

### 3.2 MacBook 触控板

- `wheel + ctrlKey` 继续作为 WebKit 中的捏合输入，并由预览舞台的非被动监听器独占。
- 捏合围绕当前手势中心连续缩放，保持该图像点处于手势中心下方。
- 捏合灵敏度从当前值提高约 2 倍；实施以 `0.004` 的指数系数为初始目标，并在真实 MacBook 上以连续、可控、无明显迟滞为验收标准微调。
- 同一动画帧内的输入在对数倍率空间合并，再进行一次视口更新，避免逐事件 React 重绘，同时不丢失细小手势增量。
- 主图继续只使用即时 CSS transform，不给缩放位置添加过渡动画，以免产生滞后或回弹错觉。
- 普通双指滚动继续平移已经放大的图像，保留水平、垂直和斜向分量，在计算出的图像边界停止，且不得触发上一张或下一张。
- 指针拖拽、双指平移、捏合和工具栏按钮必须更新同一个视口状态模型。

若调整后的 WebKit 事件方案仍未通过真实 MacBook 验收，应暂停完成声明，并另行使用现有设计允许的 macOS 原生手势适配器，把原生 magnification 事件规范化到同一视口动作；不得建立第二套缩放状态。

### 3.3 放大镜位置与显隐

- Q 键和工具栏按钮继续控制同一个启用状态。
- 普通鼠标箭头保持可见，放大镜位于指针旁，继续使用现有间距和窗口边缘自动翻转、夹取逻辑。
- 鼠标离开实际图像范围时收回镜片但记住启用状态；再次进入时重新弹出。
- 镜片位置随指针逐帧直接更新，`left`、`top` 或位置变量不得加入 CSS transition，避免拖尾。
- 主图缩放、平移、旋转或代理替换为原图后，在下一帧按最新视口和指针坐标重新计算采样。

### 3.4 更明显的弹出与收回动画

- 弹出：透明度从 0 到 1，外壳从约 70% 放大到 100%，从指针侧的变换原点产生轻微回弹，总时长约 180 ms。
- 收回：透明度从 1 到 0，外壳缩至约 80%，总时长约 140 ms。
- 只对透明度、外壳缩放和必要的阴影强度做动画，不对镜片位置或内部原图定位做动画。
- 显隐动画在 Q、工具栏切换以及启用状态下进出图像区域时一致工作。
- `prefers-reduced-motion: reduce` 下取消缩放和回弹动画，保留即时、可理解的显隐状态。

## 4. 视口与图像几何

### 4.1 状态模型

移除旧的 `original` 显示模式。视口只需要：

- `fit`：当前旋转与窗口几何下的适窗基准，倍率固定为 1；
- `free`：相对于适窗基准的自由倍率；
- 旋转角度；
- 舞台 CSS 像素中的 x/y 平移。

`displayScale` 仍输出把原图坐标转换到舞台 CSS 像素的实际比例，但百分比使用自由倍率而非该物理比例。自由模式的实际比例为 `fitScale × relativeZoom`。

### 4.2 表示无关的几何

视口几何的 source size 必须来自当前文件的原始方向修正尺寸，而不是当前代理位图的尺寸。代理图显示时也按原始尺寸建立 CSS 盒或等价的归一化映射，因此：

- 代理到原图替换不会改变 fitScale；
- 指针到原图坐标的映射无需在两个表示尺寸间临时改变视口状态；
- 旋转、锚点缩放和平移边界在两种表示下保持一致。

如果打开时原始尺寸元数据尚未得到，可先使用代理携带的源尺寸信息；取得权威原图尺寸后，只有尺寸确实变化时才重新计算并夹取几何。

### 4.3 放大镜采样比例

放大镜的原图元素以原始像素尺寸为基础，内部实际 CSS scale 使用：

`mainDisplayScale × selectedMagnification`

其中 `mainDisplayScale` 是当前视口从原图坐标到舞台 CSS 像素的实际比例。采样中心继续通过舞台坐标的逆旋转、逆平移和逆缩放得到，并在旋转后的图像范围内验证。

## 5. 加载、资源与异常

- 打开当前图片时可以并行请求适窗代理和当前原图；先到达的可用代理用于占位，原图到达后成为最终表示。
- 每次只保留一个当前实体的原图请求和一个解码后的当前原图。切换图片、关闭预览或源修订变化时取消或失效旧请求，并释放旧引用。
- 相邻图片最多预取现有适窗代理，不预取多张完整原图，避免解码峰值与持续发热。
- 原图继续受现有单图 `1 亿像素 / 700 MB` 安全预算约束，不得为满足本功能绕过预算。
- 原图超出预算时，主图继续使用高清适窗代理并提示 `原图超出安全预览限制，已继续使用适窗预览。`
- 其他原图加载失败时，主图继续使用代理并提示 `无法加载原图，已继续使用适窗预览。`
- 上述回退状态下，缩放、平移、旋转和导航仍可用；放大镜显示对应的原图不可用状态，不伪装成高清细节。
- 取消、导航和组件卸载不属于错误，不应闪现失败提示。

## 6. 可访问性与响应式行为

- “适应窗口”、缩小、只读百分比和放大按钮保持稳定的可访问名称与工具栏顺序。
- 百分比变化继续通过礼貌的 live region 或现有等价语义宣布，但连续捏合不得制造不可控的高频播报；应在交互稳定后合并播报或使用现有浏览器可接受的节流策略。
- 放大镜按钮继续暴露 `aria-pressed`、`aria-keyshortcuts="Q"` 和 Q 提示。
- 显隐不能只靠颜色表达；强制颜色模式继续保留清晰边界。
- 小窗口与 200% 页面缩放下，镜片必须被夹取在预览舞台内，工具栏与导航保持可达。

## 7. 验证策略

### 7.1 纯函数与组件测试

- `100%` 等于适窗基准，`150%` 等于 `fitScale × 1.5`；删除旧 original 模式断言。
- 窗口调整、0/90/180/270 度旋转、自由倍率和边界夹取。
- 中心及非中心锚点缩放，连续小增量合并，以及 `10%–800%` 限制。
- 普通双指滚动保留二维分量且不导航。
- 代理与原图使用同一源几何，替换前后 transform、缩放、平移和指针采样不跳动。
- 当前原图自动请求、切换取消、旧结果隔离、放大镜复用且不重复请求。
- 镜内 scale 等于主图实际 displayScale 与 1.5/2/3 倍的乘积，包括自由缩放和所有旋转。
- 弹出、收回、图像区域进出和减少动态效果下的显隐状态。
- 原图预算错误、普通错误、恢复和导航后的状态清理。

### 7.2 视觉与原生验收

- 更新单图预览正式场景，使工具栏只出现一个适窗基准和一个百分比读数。
- 记录适窗 100%、自由缩放、旋转、原图已替换和活动放大镜状态的稳定截图。
- 放大镜验收图必须能明确看出 70% 到 100% 的弹出状态或由自动动画状态测试补充证明；静态截图不单独声称验证动态效果。
- 运行现有 UI、Rust、lint、类型、覆盖率、安全与原生验收门禁。
- 使用真实 MacBook 触控板检查：轻微捏合响应、连续快速捏合、中心锚定、水平/垂直/斜向平移、四边停止、无页面缩放、无图片导航。
- 实机检查 Q 与按钮切换、鼠标箭头保留、镜片跟随无拖尾、进出图片恢复，以及 1.5/2/3 倍随当前主图倍率正确联动。
- 检查快速切图、连续缩放和反复开关放大镜后，只保留当前原图且无持续异常 CPU 占用。

## 8. 不在本次范围

- 多图对比界面的倍率语义重构；
- 任意数值的放大镜倍率或可拖拽调整镜片尺寸；
- 绕过原图解码安全预算；
- 预加载整个文件夹的完整原图；
- 在 WebKit 手势方案通过实机验收前直接引入第二套 macOS 原生视口实现。
