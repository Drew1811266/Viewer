> Status: 0.3.1 development baseline — not a release note
>
> 基线：`0.3.0`。本页只记录当前代码已经具备的增量行为，避免把设计稿写成已交付功能。

## 1. 生成计划

0.3.1 新增"生成计划"：Agent 在对话里定下要生成什么，写进项目；用户在 Viewer 里
**只看和标记**，不编辑。

### 1.1 两层结构

| 层 | 内容 | 谁读 |
| --- | --- | --- |
| 第一层 | 计划、组、`declaredCount`、组意图 | 人，全量读 |
| 第二层 | 分镜、共享取值片段、参考图、规格、模型 | 机器读，人抽样 |

画布只画第一层；声明数量与实际分镜数不一致时，组节点显示 `⚠ 声明 N · 实际 M`。

### 1.2 协议与存储

- `viewer.plan/1`：`.viewer/plans/incoming/<planId>/<revision>.json`，写入后不可变。
- `viewer.plan.run/1`：`.viewer/plans/runs/<planId>/<runId>.json`，重试不升 revision。
- `viewer.plan-marks/1`：`.viewer/plan-marks/<planId>/current.json`，由 Viewer 写。
- 参考图：`.viewer/refs/<sha256>`，按内容寻址，同一份字节只有一个文件。

### 1.3 用户能做的事

切换计划、平移缩放、选中节点、打标记、删除标记、看变更。**没有编辑，也没有批准。**

标记状态由当前 revision 与 `observedHash` 派生：待处理 / 已改 / 已换 / 已失效。
空标记不等于通过；Agent 不得把"没有标记"解释成"用户认可"。

### 1.4 集成方式

- `viewer-plan-mcp`：stdio 子进程形式的 MCP 服务，8 个工具（`plan_rules`、
  `plan_validate`、`plan_write`、`plan_current`、`plan_list`、`plan_run_record`、
  `marks_read`、`assets_import`）。不开端口、不常驻。
- `viewer-plan-reader` + `scripts/plan-protocol/*.mjs`：本地读取 CLI。
- 详见 [plan-protocol.md](../protocol/plan-protocol.md) 与 ADR 0012。

## 2. 已知限制

- 界面目前只画第一层；下钻、标记筛选、按维度过滤尚未实现。
- `plan_validate` 对未知字段/类型错误只给行列号，不给 JSON 路径。
- 计划列表的有效版本判定会跳过不可解析的版本文件并记录原因，但不会自动清理它们。
- 本版本是开发基线，未打包、未签名、未公证。
