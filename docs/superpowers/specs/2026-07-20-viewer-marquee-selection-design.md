# Viewer 图片框选交互设计

**日期：** 2026-07-20

**状态：** 已确认，待实现
**范围：** Viewer 0.1 / M3 图片网格选择

## 1. 背景与目标

M3 Finder 导出实机验收确认了单文件卡片主体可以启动原生复制拖拽，但也暴露出一个独立的选择交互缺口：图片网格只支持单击、Command 切换、Shift 连选、方向键和全选，没有实现从网格空白处拖出选择框。用户尝试框选时既不会改变选择，也没有视觉反馈，因此难以自然地建立多文件选择并执行对比、批量操作或 Finder 导出。

本设计为图片网格增加符合 macOS 生产力工具习惯的框选，同时保持三种拖动手势从按下开始就有唯一所有者：

- 网格空白处拖动：Viewer 图片框选；
- 图片卡片主体拖动：复制到 Finder；
- 图片卡片“⋮⋮”拖柄拖动：Viewer 内部移动或 Option 复制。

## 2. 方案选择

采用 WebView DOM 选择层，并由 `VirtualGrid` 使用自己的规范布局数据进行命中计算。图片虚拟网格捕获从自身空白背景开始的指针会话、绘制选择框，并用当前容器宽度、列数、单元格尺寸、间距和滚动位置计算全部图片的内容坐标矩形。虚拟化只决定哪些卡片挂载，不影响哪些图片可以被框选命中。

不在 `ContentBrowser` 中复制一套独立行列数学模型，因为响应式列数、缩略图尺寸切换和虚拟滚动会让两个布局真相源产生偏差。不采用 AppKit 原生覆盖层，因为它会增加 WebView/原生坐标、滚动与生命周期同步，并与已经独立的原生 Finder 拖拽会话产生不必要耦合。

## 3. 交互规则

### 3.1 启动与手势所有权

- 仅主鼠标键在图片网格空白背景按下时可以启动框选。
- 从卡片、卡片子元素、控件或整理拖柄按下时不得启动框选。
- 指针移动达到 4 CSS px 阈值后显示选择框；未达到阈值的背景单击只清空当前选择。
- 框选开始后使用 Pointer Capture 保持会话，直到 `pointerup`、`pointercancel`、Escape、组件卸载或工作区替换。
- `pointercancel` 或 Escape 会恢复会话开始时的选择快照；工作区替换或卸载只清理低层会话，现有工作区同步逻辑继续负责剔除失效实体。
- 框选期间禁止文本选择和浏览器原生拖拽；结束后必须恢复正常状态。

### 3.2 选择语义

- 普通框选以会话开始时的选择快照为基准，用当前选择框命中的图片集合替换原选择。
- Command 框选冻结会话开始时的选择快照，并对命中图片执行切换：原来已选的取消，原来未选的加入。
- Shift 仍用于现有的连续范围选择，不为框选增加第二种合并语义。
- 命中采用矩形相交规则；选择框触及卡片可见边界即命中。
- 每次实时选择更新都通过现有 `commitSelection` 数据流同步给父级，因此批量工具栏、对比入口和拖拽冻结逻辑继续使用同一个选择真相源。
- 框选结束后，活动项和锚点设为按当前可见顺序排列的第一个命中图片；没有命中时清空活动项和锚点。

### 3.3 视觉反馈

- 选择框位于网格内容坐标系中，显示半透明系统蓝填充、1 px 蓝色描边和轻微圆角。
- 已命中卡片沿用现有 `aria-selected=true` 高亮，并随框移动实时更新。
- 框选期间网格显示十字选择光标，选择框设置 `pointer-events: none`，不遮挡命中检测。
- 选择框只覆盖图片网格，不跨越工具栏或文本文件列表。

### 3.4 自动滚动

- 指针进入网格可视区域顶部或底部 32 px 时开始垂直自动滚动。
- 速度随指针靠近边缘而增加，上限为每动画帧 18 CSS px。
- 每个动画帧在滚动后根据 `VirtualGrid` 的规范布局数据重新计算内容坐标和实时选择。
- 指针离开边缘区、会话结束或无法继续滚动时停止动画帧循环。
- 命中计算覆盖全部图片，而不是只覆盖当前挂载项；因此跨屏框选和反向缩小选择框都不会受到虚拟化卸载影响。

## 4. 组件边界与状态

`VirtualGrid` 继续负责虚拟布局和滚动，并新增一个可选的低层框选接口。它拥有指针起点/当前点、Pointer Capture、选择框几何、边缘自动滚动动画帧和基于规范布局的命中计算；它只向调用方发出有序实体键、会话阶段与开始时的 Command 状态，不拥有业务选择。

`ContentBrowser` 拥有业务选择语义：

- 会话开始时的选择快照；
- Command 模式快照；
- 当前命中实体集合；
- `commitSelection`、活动项和选择锚点的更新。

几何与自动滚动速度计算提取为无 React 状态的纯函数，接收两个点、规范网格布局和视口边界，返回规范化选择矩形、命中键与滚动增量。这样可以单独测试正向/反向拖动、边界相交、全部虚拟项目和滚动坐标转换。框选不调用 Rust、不接触文件路径，也不改变 Finder 或内部整理拖拽协议。

## 5. 可访问性与降级

- 图片网格保留 `role="listbox"`、`aria-multiselectable="true"`、`aria-selected` 和现有键盘语义。
- 选择框作为纯视觉反馈并标记为 `aria-hidden="true"`；屏幕阅读器继续依赖已选项状态和工具栏计数。
- 不支持精确指针或 Pointer Capture 的环境仍可使用点击、Command、Shift、Command-A 和“全选当前文件夹”。
- 文本文件列表本次不增加框选；它仍使用现有点击和键盘多选，避免在一项 Finder 拖拽验收修复中扩大为跨布局选择重构。

## 6. 测试与验收

实现必须先增加失败测试，再修改生产代码。自动化覆盖：

1. 空白背景普通框选实时替换图片选择，并渲染可见选择框；
2. Command 框选按会话开始快照切换命中项；
3. 反向拖动和边界相交命中正确；
4. 背景单击清空选择；
5. 从卡片主体开始不会启动框选，仍只调用一次 Finder 导出；
6. 从“⋮⋮”开始不会启动框选，仍保留内部移动/Option 复制；
7. Pointer cancel、Escape、工作区替换和卸载会清理选择框、Pointer Capture 与自动滚动；
8. 边缘自动滚动会更新选择且在会话结束后停止；
9. 原有点击、Command、Shift、键盘、文本选择和全选测试继续通过。

实机验收使用重新打包的 Viewer：从图片网格空白处拖出可见选择框，同时选中 JPG 与 PNG，然后从任一已选卡片主体拖到 Finder。目标目录中必须同时出现两个文件，并与源文件 SHA-256 一致。通过后才继续 M3 的文本导出、取消、内部整理、Finder 导入和重启后导出验收。

## 7. 非目标

- 不为文本列表增加框选；
- 不增加横向自动滚动或跨图片/文本区域的选择框；
- 不更改 Finder 导出、内部整理、文件命令或 Rust 安全边界；
- 不新增偏好设置、自定义框选颜色或触控板专用手势。
