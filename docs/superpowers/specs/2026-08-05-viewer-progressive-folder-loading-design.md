# Viewer 渐进式文件夹加载与缩略图缓存设计

> 状态：方案 2 与全部设计章节已批准，等待书面规格复核
>
> 日期：2026-08-05
>
> 适用分支：`codex/viewer-atlas-product-migration`

## 1. 决策摘要

Viewer 当前的文件夹切换把“文件夹结构查询”和“可见缩略图加载”合并成了一个全局阻塞过程。任一可见缩略图仍在请求时，内容网格会被整体设为透明、侧边栏进入加载态，根目录入口也会消失，再由全覆盖加载层代替。这会制造明显闪白，并让本可渐进显示的图片看起来像是整体加载变慢。项目首次打开还存在一个仅为历史视觉验收加入的固定 `600ms` 延迟。

本设计采用已经批准的方案 2：移除人工延迟，将文件夹数据和缩略图加载拆成两个层级；新文件夹结构就绪后立即渲染稳定网格，缩略图逐项出现；同时建立项目会话级、跨内容表面的有界共享缓存。缩略图任务保留为非阻塞进度信息，但不再控制侧边栏、根目录入口或整个内容区的显隐。

本次只优化 macOS 当前开发版的产品代码，但数据与组件边界保持平台无关，可被后续 Windows 版本复用。

## 2. 现状与根因

### 2.1 人为首屏延迟

`useProjectSessionController` 在原生项目打开后调用 `holdNativeInitialProjectionForVisualStability()`，固定等待 `600ms` 才查询初始投影。该延迟原本用于稳定视觉验收截图，现在直接增加了真实用户等待时间，且自动化测试模式默认绕过它，导致日常测试无法暴露这项退化。

### 2.2 缩略图任务错误地升级为全局加载状态

`App` 通过 `thumbnailTask?.status === 'running'` 计算全局 `thumbnailLoading`，并据此：

- 隐藏项目根目录按钮；
- 让 `FolderTree` 进入加载态；
- 在内容表面设置 `data-thumbnail-loading`；
- 渲染全覆盖的 `WorkspaceLoadingState`。

对应 CSS 会把整个 `ContentBrowser` 设为透明并禁止交互。只要最后一张可见缩略图尚未结束，用户就看不到已经完成的数据和图片。这是切换时闪白的直接原因。

### 2.3 缓存生命周期过短且表面之间不共享

`ContentBrowser` 内部使用组件级 `Map` 缓存缩略图 URL 和在途 Promise。直接在两个内容文件夹间切换且该组件实例未卸载时，缓存可以复用；一旦切到文件夹概览或其它导致组件卸载的表面，缓存就会丢失。`FolderOverview` 的胶片条也不复用内容网格的缩略图结果，因此同一图片会被再次请求。

现有虚拟网格只挂载可见行和少量 overscan，这一“屏幕内优先”的按需加载行为是正确的，应继续保留。

## 3. 目标与成功标准

### 3.1 目标

- 项目首次打开不再承受固定 `600ms` 等待；
- 文件夹点击后立即显示选中反馈，不因图片任务冻结侧边栏；
- 新文件夹数据就绪后立即显示稳定布局，图片在各自固定位置渐进出现；
- 已完成图片不等待其它图片，不出现整页遮罩、网格清空或闪白；
- 内容网格、文件夹概览和胶片条共享同一项目会话的缩略图结果；
- 同一个缩略图的并发请求合并，返回已访问位置时优先命中缓存；
- 快速连续切换时，过期查询不能让内容回跳；
- 自动化测试可用确定性延迟证明上述行为，不再依赖反复操作大量真实文件。

### 3.2 用户可见完成条件

以下条件必须同时满足：

1. 点击文件夹后，侧边栏选中状态在下一次 React 提交中可见；
2. 文件夹元数据返回后，新网格立即显示文件名、稳定图片槽位和逐项占位；
3. 缩略图加载期间，侧边栏、根目录入口和内容浏览器保持可见、可滚动、可继续切换；
4. 单张图片完成后立即替换自身占位，不等待同批其它图片；
5. 返回已访问文件夹时，缓存命中的缩略图不产生新的桥接请求；
6. 连续选择三个文件夹时，最终只显示第三个文件夹，较早请求即使晚返回也被忽略；
7. 项目首次打开仍允许真正的整体加载态，但整体加载态只由项目/工作区数据是否存在决定，不由缩略图任务决定；
8. 文件夹查询超过 `120ms` 才显示低干扰进度线，快速查询不出现短暂闪烁。

## 4. 范围与非目标

### 4.1 本次范围

- 移除固定的原生初始投影等待；
- 明确区分项目初始加载、文件夹投影查询和缩略图加载；
- 文件夹选择的即时反馈、延迟进度提示和竞态保护；
- 项目会话级缩略图 Promise/URL 共享缓存；
- 内容网格、文件夹概览及其胶片条接入共享缓存；
- 与这些行为直接相关的组件测试、控制器测试、样式契约和原生冒烟。

### 4.2 非目标

- 不改变已批准的 Viewer 视觉语言、网格密度或文件夹交互逻辑；
- 不在本轮预取相邻文件夹或扫描整个项目的缩略图；
- 不改写 Rust 图像解码管线，除非测量证明前端消除阻塞后仍存在独立后端瓶颈；
- 不用模糊、淡入或全屏交叉淡化掩盖加载；
- 不无限缓存所有浏览过的缩略图；
- 不在本轮开发 Windows 原生壳；
- 不通过修改系统分辨率、缩放或 Dock 状态完成验收。

## 5. 加载状态模型

### 5.1 三层状态

加载状态拆成三层，禁止互相升级：

1. **项目初始加载**：项目已经打开但 `workspace` 尚不存在。允许显示完整的工作区加载状态和侧边栏骨架。
2. **文件夹投影查询**：用户已选择目标文件夹，正在查询文件树/工作区元数据。侧边栏立即反馈目标选中；现有可用内容暂时保留。只有查询超过 `120ms` 时，内容区顶边显示细进度线。
3. **缩略图加载**：新工作区已经渲染，每个图片槽位自行请求和显示结果。该状态只影响对应图片单元和紧凑任务反馈，不改变应用主体显隐或可交互性。

`thumbnailTask` 可以继续驱动 `TaskBar` 的非阻塞进度，但不得再作为 `FolderTree loading`、项目根目录按钮或 `WorkspaceLoadingState` 的条件。

### 5.2 文件夹切换时序

文件夹切换使用以下时序：

1. 用户选择文件夹；
2. 控制器记录新的目标文件夹和单调递增的 `requestId`；
3. 侧边栏立即呈现目标选择反馈；
4. 启动 `folderTree` 与 `queryFolder` 请求，并启动 `120ms` 延迟提示计时器；
5. 在元数据返回前保留当前可用内容，避免空白；
6. 当前 `requestId` 的数据返回后，原子提交新文件树、工作区和选择上下文；
7. 新内容立即渲染稳定槽位，可见缩略图按现有虚拟化顺序发起请求；
8. 每张缩略图完成后只更新自身；
9. 过期 `requestId` 的成功或失败结果全部忽略；
10. 请求结束时清除延迟提示计时器和投影查询状态。

保留旧内容只发生在短暂的“元数据尚未返回”阶段；一旦新元数据返回，立即切到新文件夹的占位网格，不等待任何图片。设计不采用等待首屏图片后再切换，也不采用整个界面的交叉淡化。

### 5.3 延迟进度线

投影查询提示是内容表面顶边的一条安静细线：

- 查询在 `120ms` 内完成时从不挂载；
- 挂载后不改变布局高度，不遮挡内容，不阻止交互；
- 仅表示文件夹结构查询，不跟随单张缩略图进度；
- 请求完成、失败、被新请求取代或项目关闭时立即清理；
- 尊重 `prefers-reduced-motion`，不依赖持续位移动画传达状态。

## 6. 项目会话级缩略图缓存

### 6.1 边界与接口

新增一个由 `ViewerWorkspace` 持有的项目会话级缩略图缓存。缓存对消费组件暴露稳定请求函数，职责只有：构造键、返回缓存结果、合并在途请求、限制容量和在会话切换时清理。图片组件仍只负责占位、成功和失败三种本地显示状态。

接口语义如下：

```ts
interface ProjectThumbnailCache {
  request(file: BrowserFile, maxPixels: number, scaleMilli: number): Promise<string>
  clear(): void
}
```

`ViewerWorkspace` 以当前 `projectSessionId` 创建或重置缓存，并把同一个 `request` 函数传给 `ContentBrowser` 与 `FolderOverview`。胶片条通过 `FolderOverview` 使用同一函数。组件不再各自拥有互不相通的 URL/Promise 缓存。

### 6.2 缓存键和失效

缓存键必须包含：

```text
projectSessionId + entityId + modifiedNs + maxPixels + scaleMilli
```

- `projectSessionId` 防止跨项目碰撞；
- `entityId` 标识文件；
- `modifiedNs` 让已修改文件自然产生新键；
- `maxPixels` 与 `scaleMilli` 防止错误复用不匹配分辨率。

项目会话变化时整体清空缓存。单个请求失败时立即删除对应键，允许后续重试；失败结果不进入 LRU。文件修改产生新键后，旧键只作为普通冷条目等待 LRU 淘汰。

### 6.3 Promise 合并与 LRU

缓存分成两个内部集合：

- `inFlight` 保存尚未完成的 Promise；
- `resolved` 保存已经完成的 URL，并按 LRU 顺序排列。

第一次请求创建 Promise 并立即放入 `inFlight`。相同键的后续调用返回同一 Promise，因此内容网格和胶片条不会同时重复调用 `bridge.requestImage`。Promise 成功后从 `inFlight` 移除并把 URL 写入 `resolved`；失败后只从 `inFlight` 移除，不缓存失败。

`resolved` 最多保留 `512` 个键。每次命中刷新访问顺序；超出容量时从最久未使用的已完成条目开始淘汰。`inFlight` 不参与 LRU 淘汰，保证并发同键始终只产生一次桥接调用；它的规模由现有虚拟化挂载范围自然限制。缓存值是桥接返回的 URL/令牌，不是前端自行持有的解码像素缓冲，因此 512 项在限制请求重复和控制前端内存之间更平衡。

`clear()` 清空两个集合并递增内部 generation。旧 generation 的在途 Promise 即使稍后成功，也不得重新写入已清空的 `resolved`。如果未来桥接 URL 增加显式释放要求，淘汰和 `clear()` 必须同步调用该正式释放接口；本次不虚构尚不存在的释放能力。

### 6.4 请求优先级

不新增主动调度器。继续依靠现有虚拟网格只挂载可见行和少量 overscan 的机制，让屏幕内项目自然先发起请求。文件夹概览只为实际挂载的胶片项请求图片。本轮不后台预取相邻文件夹，以避免大型项目中的无效磁盘读取。

## 7. 组件与代码边界

### 7.1 `useProjectSessionController`

- 删除 `NATIVE_INITIAL_PROJECTION_HOLD_MS`、`holdNativeInitialProjectionForVisualStability` 和相关状态；
- 项目打开后立即调用初始 `refreshProjection`；
- 保留并强化单调 `projectionRequestRef` 竞态保护；
- 在 `ViewerState` 新增 `projectionTransition`，值为 `null` 或 `{ selectedFolderId, selectedFolderPath, showingAggregate }`；`projection_requested` 立即写入目标，`projection_loaded`、当前请求的 `projection_failed` 和项目关闭负责清空；
- 投影失败只处理当前请求，过期失败不得覆盖当前状态。

### 7.2 `App` / `ViewerWorkspace`

- 创建项目会话级缓存并提供稳定的共享缩略图请求函数；
- 用 `state.workspace === null`（结合现有项目状态）定义真正的初始工作区加载；
- 移除缩略图任务对侧边栏、项目根目录入口和全覆盖加载层的控制；
- 侧边栏选择使用 `projectionTransition?.selectedFolderId ?? selectedFolderId`，内容区仍使用最后成功提交的 `workspace`，从而实现即时反馈而不提前混用新旧数据；
- 将文件夹查询延迟提示挂在内容表面，不覆盖内容；
- 保留紧凑 `TaskBar` 和当前已有的任务行为；本轮不新增缩略图取消协议。

### 7.3 `ContentBrowser` 与图片单元

- 接收共享的 `requestThumbnail`；
- 删除组件内部重复的 URL/Promise 缓存；
- 保留虚拟化、稳定宽高比槽位和逐项 `AspectThumbnail` 状态；
- 新工作区 props 到达后立即渲染元数据与占位；
- 单张失败仅在自身显示错误/占位，不影响其它单元。

### 7.4 `FolderOverview`

- 接收同一个共享 `requestThumbnail`；
- 胶片条与内容网格复用相同键和在途请求；
- 文件夹图片列表查询仍维持自己的数据职责，不与像素表示缓存混合；
- 组件卸载不再导致项目会话缩略图缓存丢失。

### 7.5 样式

- 删除或停用“缩略图加载时让整个内容浏览器透明”的规则；
- 删除缩略图加载专用的全覆盖 `WorkspaceLoadingState`；
- 保留图片槽位本地占位样式和稳定几何尺寸；
- 新增不占布局的延迟进度线，并覆盖 reduced-motion 状态；
- 不引入大面积淡入淡出，避免再次产生亮度闪烁。

## 8. 错误、取消与竞态

### 8.1 文件夹查询失败

当前请求失败时：

- 保留最后一次成功提交的工作区，不清空内容；
- 清除目标文件夹的待处理状态和延迟进度线；
- 通过现有全局通知体系显示可恢复、非阻塞错误；
- 用户可以重新选择同一文件夹或其它文件夹；
- 不把文件夹查询错误伪装成图片加载错误。

### 8.2 缩略图失败

单张请求失败时删除缓存条目，只更新对应图片单元。其它图片继续加载，侧边栏和网格保持可交互。后续重新挂载或明确重试可以重新发起请求。

### 8.3 快速连续切换

每次投影查询获得唯一递增 `requestId`。只有当前 ID 可以提交工作区或错误；旧请求完成后静默退出。项目关闭、重选或会话变化还要递增会话 epoch/请求编号，保证旧项目结果无法进入新会话。

### 8.4 计时器清理

`120ms` 提示计时器必须在成功、失败、新选择、项目关闭和组件卸载时清理。测试使用受控假计时器证明不存在卸载后更新或旧请求重新显示进度线的问题。

## 9. 测试策略

### 9.1 测试驱动顺序

实现按红—绿—重构推进，先写失败测试再修改产品代码：

1. 控制器测试证明项目打开不会调用或等待固定 `600ms`；
2. `App` 测试证明缩略图任务运行时侧边栏、根目录入口和内容浏览器仍可见；
3. 内容浏览器测试证明元数据到达后占位立即出现、单张完成后独立显示；
4. 缓存单元测试证明键、Promise 合并、失败删除、命中刷新、512 项 resolved LRU、清理 generation 和会话清理；
5. 集成测试证明内容网格与文件夹概览共享命中，不重复调用桥接；
6. 控制器竞态测试证明最后选择获胜，过期成功和过期失败均被忽略；
7. 假计时器测试证明 `120ms` 前无提示、之后显示、结束后清理；
8. CSS/DOM 契约测试证明不存在缩略图任务导致的全网格透明或全覆盖遮罩。

### 9.2 确定性性能场景

测试桥接分别提供可控的文件夹查询 Promise 和单张缩略图 Promise。测试不依赖真实等待，而是主动释放指定请求，并断言每一步的 DOM：

- 文件夹查询未完成：目标选择已反馈、旧内容仍存在；
- 查询完成而图片未完成：新元数据和全部稳定占位已出现；
- 释放一张图片：只有对应单元出现图片；
- 其它图片仍挂起：网格和侧边栏仍可操作；
- 返回已访问文件夹：桥接调用计数不增加；
- 依次释放旧、新查询：最终内容不回跳。

该方案替代依靠长时间真人式重复点击发现竞态的做法，使核心性能体验在单元/集成测试中快速且可重复验证。

### 9.3 原生冒烟

自动化通过后只运行一次固定原生流程：

1. 冷启动并打开测试项目；
2. 连续切换两个未访问文件夹；
3. 返回第一个已访问文件夹；
4. 快速依次点击三个文件夹；
5. 在文件夹概览和内容网格之间切换；
6. 验证窗口可继续滚动、选择和再次切换；
7. 收集一次前后请求计数与关键时间点。

原生冒烟使用应用默认窗口和当前系统设置。禁止修改显示分辨率、缩放或 Dock；若未来确需验证特定系统环境，必须先快照、结束后恢复并用系统状态读回验证。

## 10. 性能与视觉验收

### 10.1 记录指标

在同一测试项目和同一构建下记录优化前后：

- 项目打开请求到初始 `queryFolder` 发起的间隔；
- 文件夹点击到选择反馈的时间；
- 文件夹点击到新元数据/占位网格可见的时间；
- 第一张可见缩略图出现时间；
- 当前可见缩略图全部结束时间；
- 首次访问和返回访问的 `requestImage` 调用数；
- 快速三连切换后的最终工作区身份；
- 控制台错误、未处理 Promise 拒绝和 React 卸载更新警告。

### 10.2 通过标准

- 固定 `600ms` 人为延迟为 `0`；
- 点击选择反馈不依赖文件夹或图片请求完成；
- 文件夹元数据完成后不等待缩略图即可看到新布局；
- 整个切换过程中不存在内容浏览器 `opacity: 0`、全覆盖缩略图加载层或侧边栏加载闪烁；
- 单张图片完成即可显示；
- 同一缓存键的并发桥接调用数为 `1`；
- 返回仍在 512 项缓存范围内的已访问文件夹时，对缓存命中项的桥接调用增量为 `0`；
- 过期查询提交次数为 `0`；
- `pnpm verify`、受影响 UI 测试和固定原生冒烟全部通过。

这些标准关注由本次设计能直接控制的人工等待、阻塞方式、重复请求和竞态。磁盘首次读取的绝对毫秒数受图片体积、系统缓存与硬件影响，作为前后测量数据记录，不承诺不可靠的统一硬阈值。

## 11. 实施顺序与回退边界

实施按以下模块顺序进行：

1. 删除人工投影等待并补控制器测试；
2. 拆分初始加载、投影查询和缩略图任务状态；
3. 移除全局缩略图遮罩与透明样式；
4. 新增并测试项目会话级 LRU 缓存；
5. 内容网格接入共享缓存；
6. 文件夹概览与胶片条接入共享缓存；
7. 加入延迟进度线和竞态/失败行为；
8. 运行确定性集成测试、完整验证和一次原生冒烟；
9. 记录优化前后证据和剩余瓶颈。

各模块保持独立提交或至少独立可验证边界。如果共享缓存出现问题，可以回退缓存接入而不恢复整页遮罩；如果延迟进度线存在视觉问题，可以移除提示而不影响渐进加载；不得以恢复固定等待或全局透明遮罩作为回退方案。

## 12. 与既有视觉规格的关系

本设计不修改 Viewer Complete UI Visual Upgrade、Visual Atlas 或图谱到产品迁移中已经批准的界面结构和组件视觉。它补充的是加载过程契约：

- 完整加载状态只用于真正没有可用工作区的阶段；
- 图片槽位占位、错误和成功状态继续遵守正式视觉图谱；
- 新增进度线必须使用现有颜色、圆角和动效 token；
- 已批准的侧边栏、工具栏、网格、圆盘菜单和选择描边不因性能优化而重设计。

如果实现过程中发现旧视觉规格要求缩略图任务覆盖整个工作区，以本设计中用户已批准的“不中断、渐进出现”行为为准，并在实施计划中明确列出被取代的旧规则。
