# Viewer 0.3.0 视觉稿审计（2026-10-29）

> 结论：当前 21 屏不能作为 0.3.0 的实现依据。它把“Material 3 视觉升级”做成了
> 一套新的信息架构，并混入了产品没有的能力；同时存在可复现的遮挡、裁切和缩略图
> 损坏。先修正产品事实和设计范围，再重做画面。

## 1. 审计对象与方法

- 产品事实：`README.md`、`docs/PRODUCT_SPEC.md`、`docs/product/*`、`ui/src/` 与
  `crates/` 中现有的类型、组件和测试。
- 当前界面：用现有视觉验收 harness 在 `1440 × 900` 下截取，
  证据在 [`audit/current/`](audit/current/)。
- 21 屏：Pen 源文件 `/Users/abc/Project/9.22/design.pen` 的 21 个 frame，
  以及 `exports/` 中的导出。
- 结构审计：通过 Pencil MCP 读取节点边界，检查子节点是否越界、负尺寸、
  文本/图标是否在父容器内；不把截图里的“看起来像”当作唯一证据。

## 2. 产品实际是什么

Viewer 0.2.5 是 **macOS 本地图片/文本/视频浏览、轻量整理和持续评审工具**：

- 一次打开一个本地项目文件夹；没有账户、云同步、团队空间、通知中心。
- 工作区是“顶部栏 + 可折叠文件夹栏 + 内容区”，内容区以图片网格为主，
  视频和其他文件是网格下方的分区；没有左侧一级导航栏，也没有表格/列表视图。
- 图片预览是独立的全屏层：顶部工具栏 + 图片画布 + 浮动前后导航；
  文件信息是单独的“文件信息”面板，不是预览右侧常驻栏。
- 持续评审是图片预览的一种工作台状态：顶部工具栏中的“浏览/标记/意见栏/存档意见/历史/
  返回网格”，右侧 320px 意见栏；意见在栏内编辑，没有浮在画布上的 composer。
- 当前标记工具只有 **点、箭头、画笔、矩形、椭圆** 五种；颜色和线宽固定。
- 评审状态是 **保留 / 待定 / 淘汰**；没有“待评审 / 进行中 / 已完成”这套状态。
- 当前流程是“保存当前意见 → 存档上一轮 → 查看历史”，没有“开始第 N 轮评审”或
  “完成本轮评审”的强制步骤；后者只存在于旧版固定范围评审，不是生产持续评审主流程。
- 历史是 **大尺寸模态面板**，不是独立统计页；迁移是 **候选意见列表模态**，
  不是复制素材的进度页。
- 设置是 **模态设置面板**：缩略图大小、放大镜形状/倍数/面积、视频缓存；
  语音是 0.3.0 新增，当前还没有模型设置页。
- 当前已经存在、但 21 屏完全没有覆盖的能力：多图对比、批量重命名、批量图片处理、
  重命名/复制/移动/废纸篓/冲突/操作结果、搜索分组结果、文件夹概览、径向菜单、
  信息面板、任务/错误/加载状态。

## 4. 用户指出的三类问题

### 4.1 用途被误解：图表成了主角

`数据看板.png` 同时出现在工作区卡片、列表缩略图、视频内容、评审画布、
开始/完成/冲突/迁移背景中；评审意见也在讨论“图表在深色背景下对比度不足”。
这会把“AI 素材/设计稿评审”读成“数据分析工具”。

- 处理：所有示例素材换成产品图、设计稿、移动端/桌面端界面截图；
  评审意见改为真实的视觉返工语言（间距、层级、材质、裁切、对齐）。
- 验收：21 屏中不得出现图表、KPI、统计卡作为被评审素材；历史/统计也不得用
  “意见总数/本周完成”这类无数据支撑的指标。

### 4.2 元素没有现有 UI 依据

以下元素在 0.2.5 代码中没有对应实现，也不是 0.3.0 已批准的需求：

`M3NavigationRail`、最近项目、通知、头像、网格/列表切换、待评审/进行中/已完成、
预览右侧信息/意见栏、文本预览缩放条、视频右侧信息栏、评审人/参与人、评审轮次、
开始/完成评审、Markdown 摘要导出、历史统计页/导出/12 个月保留、整页设置、
“另存为新素材”、“用默认应用打开/跳过/加入评审”、迁移复制素材进度。

处理：建立“元素来源”列，每个元素必须标记为
`当前实现` / `0.3.0 已批准` / `未来能力`；`未来能力` 不得出现在主流程画面。

### 4.3 遮挡、裁切、错位

确定的结构问题（Pencil 边界审计 + 截图）：

- 03：`Thumbnail` 内 **168 个越界节点**，`Card A/B` 等出现 `width = -6.44`，
  `Bar` 的 y 为负；列表缩略图实际是损坏的图表残片。
- 11：`Stop button` 在 720 宽的 `Voice composer` 中 `x=648,w=88`，右边缘 736，
  **被裁掉 16px**；录音面板底部贴到 900 画面边缘。
- 13：只读横幅 `y=64,h=44` 覆盖从 y=64 开始的工具轨/画布。
- 04：残留 `Eye icon` 在 `(-20,-20)`，是不可见脏节点。
- 08/09/10：`Composer` 固定覆盖画布底部（`y=700,h=156`），实际持续评审把编辑放在
  320px 意见栏内；这既是结构错误，也是遮挡。
- 08/09/10/11/12/13：意见栏宽 332，当前实现是 320；不是不能改，但必须和实现/
  响应式规则一起定，不能靠画面猜。
- 多个按钮/图标使用绝对坐标手工定位；`Paths` 的 Folder/Arrow 图标相对 64px 行
  上下偏 12px，属于需要统一的图标基线问题。

## 5. 21 屏没有覆盖的现有能力

这些不是“可选的额外画面”，而是 0.3.0 “完整 M3”必须迁移的现有界面：

1. 多图对比（2–8 张，同步/独立，缩放/旋转/移除/标记）。
2. 批量重命名；批量图片格式/尺寸/质量处理。
3. 单项重命名、复制/移动到目标、废纸篓确认、冲突逐项选择、操作结果。
4. 搜索分组/展平结果、筛选面板、文件夹概览/分类概览。
5. 图片信息面板、径向文件菜单。
6. 任务栏、加载/扫描、错误/恢复、只读恢复横幅。
7. 文本双栏/编码/编辑/外部修改冲突。
8. 视频准备/播放/暂停/结束/错误、前后视频、全屏。

如果 0.3.0 的视觉稿只覆盖 21 个“精选状态”，实现时必然出现“新 M3 外壳 + 旧样式弹窗”
的半套界面，和“完整 Material 3”目标冲突。

## 6. 建议的修正方向

### 6.1 先定一条原则

**0.3.0 是现有产品的视觉与交互升级，不是重新发明信息架构。**

除非用户明确批准新增导航/页面，否则：

- 保留顶部栏 + 文件夹栏 + 内容区；
- 保留图片预览/文本预览/视频/对比的现有承载方式；
- 保留持续评审的“图片预览 + 意见栏”，不新增一级评审页；
- 保留历史/迁移/设置/文件操作作为模态；
- 只新增 0.3.0 已批准的能力：5 个新标记工具、样式/选择/撤销、语音输入、M3 外观。

### 6.3 逐屏重做顺序

1. **事实层**：产品术语、状态、能力矩阵定稿；删除所有虚构元素。
2. **外壳**：项目入口、工作区、搜索、文件夹栏、任务/错误状态。
3. **预览**：图片/文本/视频/其他/对比；先保证当前能力 1:1，再做 M3 外观。
4. **评审**：默认 → 选中/样式 → 文字 → 语音 → 权限/错误 → 只读/归档。
5. **流程**：存档、历史、迁移、来源确认、设置。
6. **整理**：批量重命名、批量图片、文件操作、冲突/结果。
7. **附录**：工具一览、径向菜单、信息面板。
8. **验收**：逐屏对照当前截图，确认没有丢失任何现有动作。

## 7. 设计验收门槛（新增）
