## 阻止继续接入的问题

1. **可变索引与不可变文件的读取策略不同。** 正常保存会原子替换 `index.json`；已经打开的
   旧索引应可固定使用，不能把合法替换当损坏。第一版将其与不可变状态/证据使用同一严格
   路径身份规则，回归证明会拒绝并发保存。候选修正保留旧句柄并复核字节，但尚未通过完整并发验证。
2. **纯路径复查不是目录句柄约束。** Node 的路径 lstat/open 之间可以发生目录替换；仅在
   末级 open 使用 O_NOFOLLOW，再比较前后身份，不能证明整个路径始终受选定项目约束。
   真实目录替换回归已加入，包含项目内目录及项目上级目录，未模拟/伪造 OS stat 结果。
3. **补充时间戳复查引入可用性问题。** 候选方案复查所有祖先目录身份及时间戳，并有界重试。
   它能拒绝新增回归中的替换，但普通并发临时目录活动也可能触发重试/未核验，甚至让索引
   重读另一版。它不能被描述为可靠、可移植的 descriptor-relative 安全实现；在时间戳精度
   不足的文件系统上亦不能据此承诺无竞态。

因此不继续堆叠重试、放宽断言或关闭并发测试。按照 `systematic-debugging` 对反复出现的
结构性问题重新检查架构，以及 `executing-plans` 对计划缺口的暂停规则，在这里请求设计确认。
