# Viewer 0.1 Implementation Roadmap

> **For agentic workers:** This roadmap is an index. Execute each linked plan with the sub-skill declared in that plan; do not implement multiple gates in one unreviewed batch.

**Goal:** Deliver Viewer 0.1 for Apple Silicon macOS 13+ after validating the high-risk architecture and then completing milestones M1–M4.

**Architecture:** Viewer is a Tauri 2 modular monolith. React owns presentation, the cross-platform Rust core owns business state, and macOS framework access is isolated in `viewer-platform-macos`.

**Tech Stack:** Tauri 2, Rust stable, React, TypeScript, Vite, SQLite/rusqlite, Quick Look Thumbnailing, Image I/O/Core Graphics/ColorSync.

## Global Constraints

- Viewer 0.1 builds only for Apple Silicon (`aarch64-apple-darwin`) and requires macOS 13 or newer.
- Runtime content remains local; no login, telemetry, automatic crash upload, update check, or application-originated network request.
- Supported content is limited to JPG, PNG, Markdown, and TXT.
- One application session opens at most one project root.
- Original files remain in the project; Viewer never creates a second complete asset library.
- Portable marks live in `.viewer`; thumbnails, proxies, and full-text indexes are session data and are deleted when the project session closes.
- File deletion always uses the macOS Trash.
- The frontend never receives broad filesystem, shell, database, or network permissions.
- Every feature follows TDD and ends with focused tests plus a small commit.
- No public or user-facing test build is delivered until all four product milestones pass, but internal prototype and CI artifacts are allowed.

## Product Milestones After G4

Detailed milestone plans are written sequentially after G4. M2–M4 plans are created only after the preceding milestone passes review and is merged to `main`.

### M1: Browsing Core

**Status: Complete.** Implementation and accepted evidence: [M1 stage review](../../reviews/2026-07-16-m1-browsing-core-review.md).

- Project import and read-only fallback.
- Progressive folder-only tree.
- Folder overview, virtualized image grid and independent Markdown/TXT list.
- Single-image and text preview.
- Session cache lifecycle.

The next executable action is to create the M2 Review Efficiency plan with `superpowers:writing-plans` after the accepted M1 branch is merged to `main` and the M1 gate passes there.

### M2: Review Efficiency

**Status: Complete.** Implementation and accepted evidence: [M2 stage review](../../reviews/2026-07-16-m2-review-efficiency-review.md).

- Full search, filters and sorting.
- Portable file/folder review states and favorites.
- Batch marking and keyboard workflow.
- Metadata migrations and cross-computer recovery fixtures.

The next executable action is to create the M3 Organization and Comparison plan with `superpowers:writing-plans` after the accepted M2 branch is merged to `main` and the M2 gate passes there.

### M3: Organization and Comparison

- Two-to-four-image comparison.
- Batch rename, copy, move, internal drag-and-drop, Finder export and Trash.
- Session undo for marks, rename and in-project move.
- File watching, expected-change reconciliation and recovery UI.

### M4: Internal Release

- Color-management acceptance, accessibility and complete keyboard navigation.
- Security review, diagnostics export, dependency/license notices.
- Performance and long-session acceptance on the standard M4 device.
- Apple Silicon `.app` and DMG packaging; Developer ID signing/notarization when credentials are available.

## Change Control

- A gate failure updates the system architecture spec and gets reviewed before the next gate.
- Product scope changes update `docs/PRODUCT_SPEC.md` before implementation.
- A new direct dependency requires license review before merge.
- Windows code is not added during Viewer 0.1; only platform-neutral interfaces and macOS implementations are accepted.
