# Viewer 产品需求与架构文档

> Status: Active

> 文档状态：持续完善中
> 当前版本：1.6
> 更新日期：2026-07-16
> 目标平台：macOS 首发，后续支持 Windows

## 1. 产品概述

Viewer 是一款面向使用 AI 批量生成图片的设计师的本地桌面生产力工具。用户将一个项目的最高层级文件夹导入或拖入软件后，Viewer 递归索引其中的图片与文本文件，让用户不必在 Finder 中逐层进入目录，即可快速浏览、搜索、筛选、比较和整理项目内容。

首版支持 JPG、PNG、Markdown 和 TXT 文件。项目只存在于本机磁盘，不涉及云端同步、在线协作或服务器存储。

## 2. 产品定位

### 2.1 核心价值

在不改变用户现有目录组织方式的前提下，显著缩短设计师从“打开项目”到“找到、判断并整理目标素材”的时间。

### 2.2 核心用户

- 使用 AI 工具批量生成产品图、套图或设计方案的设计师。
- 项目中包含大量多层目录、多个 ID 文件夹和成组图片。
- 需要频繁浏览、筛选、比较并整理生成结果。

### 2.3 首版产品边界 `[REQ-SCOPE-BOUNDARY]`

Viewer 是本地项目查看、审阅与轻量文件管理工具，不是图片编辑器、AI 图片生成工具或云端数字资产管理系统。

首版一次只打开一个项目。用户可以切换项目，但不需要跨项目统一搜索或同时管理多个项目。

Viewer 首版仅供个人或小范围团队内部使用，不作为公开销售或面向公众分发的软件产品。

Viewer 同时被定义为开源软件，源代码计划发布到公开 GitHub 仓库。首版的主要使用范围仍是个人与团队内部；公开源码不等于提供商业支持、云服务或公开销售。

## 3. 产品原则 `[REQ-PRODUCT-PRINCIPLES]`

1. **文件系统是真实数据源**：不要求用户把源文件复制到软件资源库。
2. **本地优先**：图片、文本、索引和缓存均保留在本机，不上传用户内容。
3. **渐进加载**：先展示目录与文件元数据，再按可见范围生成缩略图，原图按需加载。
4. **高频操作低摩擦**：浏览、搜索、筛选、标记和比较支持鼠标与键盘操作。
5. **修改操作可控**：重命名、移动、删除等操作必须处理权限、重名、文件占用和撤销问题。
6. **缓存可抛弃**：索引与缩略图缓存损坏或删除后可以从源项目安全重建。
7. **目录层级不设限**：内容文件夹可能位于项目根目录下任意深度。

## 4. 核心对象

### 4.1 项目（Project） `[REQ-OBJECT-PROJECT]`

用户单次打开的最高层级本地文件夹。项目通过文件夹选择器或拖拽进入 Viewer。

### 4.2 目录节点（Folder Node） `[REQ-OBJECT-FOLDER]`

项目中的任意子目录，用于保留和展示用户原有的层级关系。

### 4.3 内容文件夹（Content Folder） `[REQ-OBJECT-CONTENT-FOLDER]`

直接包含受支持图片或文本文件的目录。内容文件夹可位于第二层、第三层或更深层级。其上级目录作为分类路径，不强制要求固定命名规则。

内容文件夹完全由扫描结果自动识别，首版不提供手动指定或排除目录的功能。隐藏目录和 Viewer 自身的 `.viewer` 目录不参与内容识别。

### 4.4 文件项（File Item） `[REQ-OBJECT-FILE]`

受 Viewer 支持和索引的本地文件：

- 图片：`.jpg`、`.jpeg`、`.png`
- 文本：`.md`、`.markdown`、`.txt`

### 4.5 标记（Marker） `[REQ-OBJECT-MARKER]`

用户对文件或内容文件夹添加的审阅信息，分为两类：

- 审阅状态：保留、待定、淘汰；同一文件同一时间只能处于其中一种状态，也可以不设置状态。
- 收藏星标：独立于审阅状态，可以与任意状态组合。

标记不写入图片或文本文件本身，而是保存在项目根目录的 `.viewer` 元数据目录中，因此项目复制或移动到另一台电脑后仍能保留。

内容文件夹的标记是文件夹自身的审阅结论，不自动继承到其文件或下级文件夹。用户如需修改文件标记，应通过多选批量操作明确执行。内容文件夹同时展示内部文件的标记统计，帮助用户判断审阅进度。

### 4.6 分类目录（Category Folder） `[REQ-OBJECT-CATEGORY]`

本身不直接包含受支持文件、但其后代包含内容文件夹的目录。选择分类目录时，主视图默认展示后代内容文件夹概览，而不是立即混合展示所有后代文件。

## 5. 已确认的核心场景

### 5.1 打开项目 `[REQ-FLOW-OPEN]`

1. Viewer 每次启动均进入空白项目入口，不自动恢复上次查看的项目或目录。
2. 用户选择“打开文件夹”，或将项目根文件夹拖入 Viewer。
3. Viewer 验证路径和读取权限。
4. Viewer 递归扫描目录并优先建立轻量元数据索引。
5. 界面尽快展示目录结构，缩略图在后台渐进生成。

### 5.2 浏览内容 `[REQ-FLOW-BROWSE]`

- 左侧结构树只显示文件夹，不显示文件；用户通过目录树定位分类目录或内容文件夹。
- Viewer 展示当前内容文件夹中的图片和文本。
- 选择分类目录时，主视图展示其后代内容文件夹概览卡片；每张卡片包含名称、相对路径、代表缩略图、图片/文本数量、文件夹标记及文件审阅统计。
- 分类目录视图提供“显示全部后代文件”入口，用户可临时聚合浏览该分类下的所有受支持文件。
- 用户可进入大图预览并通过键盘连续切换文件。
- 同名目录通过完整相对路径区分。
- 在右侧网格中单击文件只改变选择状态，不离开网格；支持标准的 `Command` 多选和 `Shift` 连续范围选择。
- 双击图片进入沉浸式预览；空格键快速打开或关闭大图。
- 方向键移动当前选择，`Enter` 进入重命名。
- Markdown 和 TXT 始终作为独立文件展示，不根据文件名与图片自动关联。
- 内容文件夹中的图片默认以缩略图网格展示，Markdown/TXT 在独立的“文本文件”区域以紧凑列表展示。

### 5.3 搜索与筛选 `[REQ-FLOW-SEARCH]`

- 顶部工具栏提供一个统一搜索框，通过 `Command+F` 聚焦。
- 默认搜索整个项目，用户可将作用域切换为“当前目录及其后代”。
- 目录名称、文件名和相对路径采用模糊匹配，并高亮匹配字符。
- Markdown 和 TXT 内容采用关键词全文检索，结果展示文件名、相对路径和匹配片段；正文不做错别字模糊匹配。
- 搜索文件名或路径时忽略大小写；具体语言的分词能力以本地索引支持范围为准。
- 筛选条件包括：文件类型、审阅状态、收藏、未标记、图片方向、像素尺寸、文件大小和修改时间。
- 同一筛选类别内的多个值采用“或”，不同筛选类别之间采用“且”。
- 关键词和筛选条件共同生效；所有生效条件以可单独移除的标签显示，并提供“一键清除”。
- 搜索和筛选在当前项目内切换目录时继续保留，关闭或更换项目后清空。
- 搜索结果默认按内容文件夹分组，也可切换为全部展平。
- 索引仍在生成时允许搜索已完成部分，并明确显示“结果仍在更新”，不得阻塞用户浏览。

### 5.3.1 排序 `[REQ-FLOW-SORT]`

- 文件默认按文件名自然升序排列，使 `2.jpg` 位于 `10.jpg` 之前。
- 文件支持按修改时间、文件大小、图片像素尺寸和审阅状态升序或降序排列。
- 内容文件夹默认按名称自然升序排列。
- 搜索结果分组视图先排列内容文件夹，再在组内应用当前文件排序。
- 展平结果对全部匹配文件应用同一排序规则。
- 当前排序在项目会话内保留，关闭或更换项目后恢复默认值。

### 5.3.2 搜索性能与反馈 `[REQ-FLOW-SEARCH-FEEDBACK]`

- 搜索输入采用短延迟防抖，用户持续输入时取消已经过期的查询。
- 元数据搜索直接读取本地索引，不访问或解码原图。
- 全文搜索只读取已索引的 Markdown/TXT 文本。
- 无结果状态应显示当前关键词、作用域和筛选条件，并提供清除筛选或扩大到整个项目的快捷操作。
- 搜索结果必须与文件系统和标记变更增量同步。

### 5.4 标记与整理 `[REQ-FLOW-ORGANIZE]`

- 用户可以给文件设置“保留、待定、淘汰”状态和收藏星标。
- 用户可以给内容文件夹设置相同的审阅状态和收藏星标，但不会自动修改其中的文件。
- 用户可以重命名、复制、移动和删除文件，所有操作均支持多选批量执行。
- 首版复制与移动的目标限定在当前项目内部。
- 用户可将文件从 Viewer 拖到 Finder，以复制方式导出到项目之外。
- 所有源文件修改都应同步更新索引、当前视图和搜索结果。
- 删除统一移动到 macOS 系统废纸篓，不提供绕过废纸篓的永久删除入口。
- 删除后由用户通过系统废纸篓恢复；应用应明确告知文件已移入废纸篓。
- 批量操作必须显示进度和结果摘要；部分文件失败时，成功项不得被错误回滚，失败项必须说明原因。
- 遇到同名冲突时，提供“跳过、保留两者、替换”选项，并允许将选择应用于本次剩余冲突。

### 5.4.1 批量重命名 `[REQ-FLOW-BATCH-RENAME]`

- 支持查找并替换文件名中的文本。
- 支持为文件名统一添加前缀或后缀。
- 支持按当前排序为所选文件添加连续编号，并允许设置起始数字和数字位数。
- 执行前展示所有原名称与新名称的对应预览。
- 执行前检查空名称、非法字符、同批次重名和目标目录已有同名文件。
- 存在错误时禁止直接执行，并定位到具体冲突项。
- 批量重命名作为一个任务和一个撤销步骤，但底层逐项记录执行结果。

### 5.4.2 内部拖拽 `[REQ-FLOW-DRAG-DROP]`

- 文件可从右侧内容区拖到左侧任意项目内目录。
- 默认拖拽语义为移动；按住 `Option` 时切换为复制。
- 拖拽期间明确高亮有效目标，并区分移动与复制状态。
- 不允许拖入项目根目录之外、隐藏的 `.viewer` 目录或没有写入权限的目录。
- 右键菜单和命令入口提供与拖拽等价的移动、复制操作。
- 将文件从 Viewer 拖到 Finder 时始终以复制方式导出，不从项目中移除源文件。

### 5.4.3 撤销与操作历史 `[REQ-FLOW-UNDO]`

- `Command+Z` 支持撤销标记、收藏、重命名和项目内移动。
- 一次批量操作作为一个用户可感知的撤销步骤。
- 撤销前重新验证源路径、目标路径和文件身份；外部变化导致无法安全撤销时停止并说明原因。
- 复制不由 Viewer 撤销，避免在用户已经使用副本后自动删除。
- 移入系统废纸篓不由 Viewer 撤销，用户通过系统废纸篓恢复。
- 撤销历史只在当前项目会话内存在，关闭或更换项目后清空。

### 5.4.4 高频快捷键 `[REQ-FLOW-SHORTCUTS]`

- `1`：标记为保留。
- `2`：标记为待定。
- `3`：标记为淘汰。
- `0`：清除审阅状态。
- `F`：切换收藏星标。
- `C`：将当前 2～4 个已选图片进入对比模式。
- `Delete`：将所选文件移入系统废纸篓。
- 当焦点位于搜索框、重命名框、Markdown/TXT 内容选择或其他文本输入控件时，停用单键快捷键。
- 快捷键动作同时适用于单选和多选；多选时在所有适用项目上执行。

### 5.5 多图对比 `[REQ-FLOW-COMPARE]`

- 用户可以同时选中 2～4 张图片进入并排对比模式。
- 对比模式服务于判断同一产品或提示词产生的不同结果。
- 支持同步缩放和同步拖动，并允许切换为各图片独立查看。
- 用户可以在不退出对比模式的情况下设置审阅状态或收藏星标。
- 当某张图片被移出对比集合时，其余图片自动重排；少于两张时退出对比模式并保留当前图片的单图预览。

### 5.6 外部文件变化 `[REQ-FLOW-EXTERNAL-CHANGES]`

- Viewer 在项目打开期间监听项目目录中的文件系统变化。
- Finder 或其他应用新增、修改、重命名、移动或删除文件时，自动增量更新目录树、内容视图、搜索索引和筛选结果。
- 普通外部变化静默处理，不用频繁通知打断用户。
- 当前正在预览、对比或选择的文件受到影响时，显示简短且可理解的状态提示。
- 对短时间内连续发生的文件事件进行合并，并优先识别重命名或移动，避免将其错误判断为“先删除、再新增”。
- 确认文件已在外部删除后，从索引和项目元数据中移除对应记录，不保留“文件缺失”项。
- 当前预览文件被删除时退出该文件预览，返回原内容视图，并尽可能保留相邻选择和滚动位置。

### 5.7 异常文件与只读模式 `[REQ-FLOW-READONLY-ERRORS]`

- 损坏、格式不完整或无法解码的图片仍保留在网格中，并显示明确的错误缩略图。
- 错误文件仍可查看基础信息、重命名、移动、复制或移入废纸篓。
- 单个文件解码失败不得中断目录扫描、缩略图队列或其他文件预览。
- 项目可读但不可写时自动进入只读模式。
- 只读模式允许目录浏览、搜索、筛选、文本预览、图片预览和多图对比。
- 只读模式禁用标记、重命名、移动、复制到项目内、删除以及 `.viewer` 元数据写入。
- 顶部持续显示只读提示，并提供打开系统权限设置或重新选择目录的入口。
- 项目连读取权限也不具备时不进入工作区，保留用户已选择的路径信息并说明如何重新授权。

### 5.8 项目与窗口生命周期 `[REQ-FLOW-LIFECYCLE]`

- Viewer 为单窗口、单项目应用。
- 每次新建主窗口都显示空白导入界面，不自动恢复历史项目或目录。
- 关闭主窗口（`Command+W`）即结束当前项目会话，停止项目监听并清理本次会话缓存。
- 从 Dock 再次打开窗口时重新进入空白导入界面。
- 退出应用（`Command+Q`）执行相同的项目结束与缓存清理流程。
- 初始扫描、文本索引、文件指纹和缩略图任务在关闭项目时静默取消。
- 如果正在执行复制、移动、重命名或删除，关闭前提示用户等待任务完成，或取消尚未开始的项目后关闭。
- 已经完成的文件操作不因关闭项目而回滚；项目元数据在每个成功操作后及时提交，不依赖退出时统一保存。

### 5.9 文本预览 `[REQ-FLOW-TEXT-PREVIEW]`

- Markdown 和 TXT 仅供预览，首版不提供编辑或保存功能。
- TXT 使用等宽或高可读正文样式展示，并支持文本选择与复制。
- Markdown 支持标题、段落、列表、引用、代码、表格、强调、分隔线和链接等常用语法。
- 禁用 Markdown 中的原始 HTML 和脚本执行。
- 禁止自动加载远程图片、样式、字体或其他网络资源。
- Markdown 本地资源只能读取当前项目根目录内部的文件。
- 用户点击外部链接时，交由系统默认浏览器打开；Viewer 内不嵌入网页浏览器。
- 自动识别 UTF-8、UTF-16 和 GB18030；无法可靠识别时提示用户手动选择编码。
- 用户手动选择的编码只影响当前预览，不修改源文件。

## 6. 初步信息架构 `[REQ-IA-SURFACES]`

- **项目入口**：每次启动显示空白导入界面，提供打开文件夹和拖入文件夹。
- **项目浏览器**：采用两栏布局。左侧为文件结构树，右侧为动态内容与预览工作区。
- **右侧动态工作区**：根据当前选择在分类目录概览、内容文件夹网格、单文件预览和多图对比之间切换。
- **沉浸式预览**：单图查看、缩放、平移、前后切换和按需文件信息。
- **对比工作区**：多图并排、同步查看、标记与文件操作。
- **任务与反馈**：扫描、缩略图生成、复制/移动进度、错误与冲突处理。
- **设置**：缓存、快捷键、默认布局与文件操作偏好。

### 6.1 主窗口布局 `[REQ-IA-LAYOUT]`

- 左栏为可调整宽度、可折叠且只显示文件夹的结构树。
- 结构树显示项目中的全部非隐藏目录，包括空目录和没有受支持文件的目录。
- 隐藏目录及 Viewer 自身的 `.viewer` 目录不显示。
- 右栏占据主要窗口空间，不设置常驻的第三栏信息面板。
- 顶部工具区域承载项目名称、路径导航、搜索、筛选、排序、视图切换和主要操作。
- 右侧工作区切换内容形态时应保留用户的当前目录上下文，避免误以为已经离开原目录。
- 需要查看详细元数据时，采用按需出现的信息浮层，而不是长期压缩图片空间。

### 6.2 单图预览 `[REQ-IA-IMAGE-PREVIEW]`

- 默认以“适应窗口”模式完整展示图片。
- 支持切换至原始尺寸（100%）和自由缩放。
- 支持触控板捏合缩放、鼠标滚轮配合修饰键缩放，以及拖动平移。
- 支持向左、向右旋转 90°；旋转只影响当前显示，不修改源文件。
- 支持方向键切换当前内容集合中的上一张或下一张图片。
- 从预览返回网格后恢复进入前的选择和滚动位置。
- 预览中可直接设置审阅状态、收藏或进入对比。

### 6.3 文件信息浮层 `[REQ-IA-FILE-INFO]`

- 通过工具栏入口或 `Command+I` 打开和关闭。
- 显示文件名、完整相对路径、文件类型、像素尺寸、文件大小、修改时间和当前标记。
- 信息浮层按需覆盖在工作区边缘，不作为常驻第三栏。
- 多选时显示已选数量、合计大小、类型分布和共同标记；不展示容易造成误解的单文件属性。

### 6.4 内容文件夹概览卡片 `[REQ-IA-FOLDER-CARDS]`

- 使用当前排序下前四张可用图片组成稳定的 2×2 代表图。
- 图片不足四张时使用已有图片填充，其余区域保持简洁的空位状态。
- 卡片显示文件夹名称、相对路径、图片/文本数量、文件夹标记和文件审阅进度。
- 缩略图生成完成后卡片渐进更新，不阻塞目录概览首次显示。

### 6.5 后台任务条 `[REQ-IA-TASK-BAR]`

- 窗口底部显示简洁任务条，用于初始扫描、缩略图生成、复制、移动、批量重命名和删除等后台任务。
- 默认状态只显示任务名称、总体进度和失败数量，不持续占用大面积工作区。
- 点击任务条展开任务详情，可查看各任务状态、已处理数量、失败项及失败原因。
- 可安全取消的任务提供取消入口；取消只影响尚未开始的项目，已经成功完成的文件操作不回滚。
- 纯后台优化任务不得抢占当前预览、搜索和用户主动文件操作的资源优先级。
- 任务完成且无错误时自动收起；存在错误时保留结果入口，直到用户查看或关闭。

### 6.6 外观、缩略图与辅助功能 `[REQ-IA-ACCESSIBILITY]`

- 默认跟随 macOS 系统浅色或深色外观，并允许用户在设置中固定为浅色或深色。
- 首版界面语言为简体中文，不提供运行时语言切换。
- 核心浏览、搜索、筛选、标记、预览、对比和文件操作均可通过键盘完成。
- 支持 macOS 系统显示缩放，并为主要控件、文件状态和任务反馈提供基础 VoiceOver 标签与焦点顺序。
- 缩略图完整适配在统一单元格内，不通过裁切填满单元格。
- 提供小、中、大三档缩略图尺寸，可通过工具栏滑杆或 `Command++`、`Command+-` 调整。
- PNG 透明区域使用清晰但不过度干扰图片的棋盘格背景。
- 缩略图单元显示文件名和审阅标记；调整尺寸时保持当前选中项和视口位置稳定。

### 6.7 色彩与方向 `[REQ-IA-COLOR-ORIENTATION]`

- 读取并尊重图片内嵌 ICC 色彩配置，预览时转换到当前显示器色彩空间。
- 没有色彩配置的图片按 sRGB 处理。
- 读取 EXIF Orientation，并以正确方向生成缩略图和原图预览。
- 临时旋转发生在 EXIF 方向校正之后，只改变当前显示，不写回源文件或元数据。
- 缩略图与原图预览应采用一致的色彩和方向处理路径，避免从网格进入大图时出现明显变化。
- 色彩管理属于显示准确性要求，但 Viewer 不承担软打样、印刷色域模拟或图片配置文件编辑功能。

## 7. 初步技术约束 `[REQ-TECH-BASE]`

- 桌面框架优先考虑 Tauri 2，核心文件与索引逻辑使用 Rust。
- 本地 SQLite 保存可重建的项目索引、搜索索引和应用元数据。
- 图片缩略图在后台按可见范围生成，macOS 首版优先使用 Quick Look Thumbnailing，失败或一致性验证不通过时回退 Image I/O，并存入本次应用会话的临时缓存目录。
- 高清预览通过 Image I/O 直接读取项目中的原始文件；应用不复制完整原图，只产生内存解码数据和可清理的视口代理。
- 原始文件保留在项目目录中，应用不建立第二份完整素材库。
- 文件系统变更需要增量反映到目录、搜索、筛选和预览状态中。
- 首版重点优化数百至约一千张、单张约 10 MB 图片的项目。
- macOS 首版只构建 Apple Silicon（arm64）版本，最低支持 macOS 13，不提供 Intel Mac 版本。

### 7.1 可迁移项目元数据 `[REQ-TECH-PORTABLE-METADATA]`

项目根目录包含由 Viewer 管理的隐藏目录：

```text
.viewer/
├── project.json
└── metadata.sqlite
```

- `project.json` 保存稳定的项目 ID、元数据版本和创建信息。
- `metadata.sqlite` 保存文件相对路径、文件指纹、审阅状态和收藏星标。
- 用户已接受 Viewer 在项目根目录创建和维护该隐藏目录。
- 不保存原图、原文或完整缩略图副本，避免显著增大项目体积。
- 项目迁移到另一台电脑后，以项目 ID 和相对路径恢复标记。
- 文件在 Viewer 内被重命名或移动时，同一事务同步更新元数据。
- 文件在 Viewer 外部被移动或重命名时，先按相对路径匹配，未匹配项再通过后台文件指纹尝试恢复关联。
- 元数据结构必须带版本号，并支持后续无损迁移。

### 7.2 文件操作一致性 `[REQ-TECH-FILE-CONSISTENCY]`

- 文件系统操作成功后才能提交索引与项目元数据变更。
- 单个批量任务由多个可独立报告结果的文件操作组成。
- 重命名和同磁盘移动优先使用原子文件系统操作。
- 复制完成后验证目标文件存在且大小一致，再报告成功。
- 文件操作期间暂停对相关路径的重复处理，避免文件监听器制造重复事件。
- 任务结束后对受影响目录执行一次轻量校验，使文件系统、索引与界面状态最终一致。
- 应用崩溃或被强制退出后，下次打开项目必须能够通过重新扫描恢复一致状态。

### 7.3 文件监听与事件归并 `[REQ-TECH-WATCHER]`

- 后台监听器只监听当前打开项目，不建立跨项目常驻监听。
- 对高频文件事件进行短时间窗口合并，避免生成工具连续写入图片时反复触发完整处理。
- 使用路径、时间、文件大小和文件指纹辅助关联重命名与移动事件。
- Viewer 自身发起的文件操作带内部任务标识，监听器不得重复执行相同索引变更。
- 外部修改图片后使旧缩略图失效，并重新按需生成；外部修改文本后更新全文索引。
- 监听器异常或事件溢出时，对受影响目录执行增量校验；无法确定范围时才执行全项目重新扫描。

### 7.4 性能基线与响应目标 `[REQ-TECH-PERFORMANCE]`

当前开发设备作为首版标准性能测试设备：

- 设备：MacBook Air
- 芯片：Apple M4，10 核 CPU
- 内存：24 GB
- 测试存储：本机 SSD
- 当前系统：macOS 26.5.2

正式性能验收使用用户后续提供的真实测试文件夹。初步参考规模为数百至约一千张、单张约 10 MB 的 JPG/PNG 图片，并包含少量 Markdown/TXT；首版暂不设置 5000 张图片压力测试门槛。

在标准设备和标准项目上，目标为：

- 冷启动至可交互空白导入界面：不超过 1 秒。
- 导入后目录树首次可操作：不超过 1.5 秒。
- 基础文件元数据扫描完成：不超过 3 秒；文件指纹和缩略图不得阻塞基础扫描。
- 已完成索引后的搜索结果响应：不超过 100 毫秒。
- 已加载目录之间的切换响应：不超过 100 毫秒。
- 约 10 MB 本地图片首次原图预览：不超过 800 毫秒。
- 浏览与滚动保持可交互，后台解码不得造成可感知的连续卡顿。

这些指标当前只对上述标准开发设备负责。最低支持范围内其他 Apple Silicon 设备需要后续兼容性验证，不能在未测试前宣称具有相同性能。

### 7.5 内存与并发预算 `[REQ-TECH-MEMORY]`

- 标准项目稳态内存目标不超过 500 MB，短时峰值不超过 700 MB。
- 原图预览只预载当前图片前后各一张，并在离开有效窗口后尽快释放解码数据与图形资源。
- 缩略图和原图解码使用有界队列，不允许为所有图片同时创建任务。
- 并发量根据设备内存和 CPU 动态调整，用户当前预览始终高于后台缩略图与文件指纹任务。
- 内存压力升高时依次停止预载、降低后台并发、释放不可见纹理和清理内存缩略图。

### 7.6 单次会话缓存 `[REQ-TECH-CACHE]`

- 缩略图、临时搜索索引和其他可重建数据仅存放在应用会话缓存中。
- 用户退出应用后自动清理本次会话缓存，不提供缓存查看或手动管理界面。
- 项目根目录 `.viewer` 中的项目 ID、文件指纹和标记属于持久元数据，不随缓存清理。
- 应用正常退出时删除会话缓存目录；因崩溃或强制结束遗留的缓存，在下次启动时后台清理。
- 单次会话仍设置内部 2 GB 安全上限，并采用最近最少使用策略控制增长，但不向用户暴露该配置。
- 磁盘剩余空间低于 5 GB 时停止新增磁盘缓存，继续使用有界内存缓存并显示非阻塞提示。
- 缓存清理不得阻塞空白导入界面的首次显示。

### 7.7 项目根目录安全边界 `[REQ-TECH-PATH-SECURITY]`

- 扫描、预览、全文索引和文件操作前均对路径进行标准化，并验证规范化后的目标仍位于当前项目根目录内。
- 首版忽略符号链接目录、符号链接文件和 macOS 别名，不跟随其目标。
- 忽略的链接不进入目录树、搜索索引或内容统计。
- 内部移动和复制的目标必须是当前项目中的真实目录，禁止写入 `.viewer`。
- Markdown 的相对资源路径应用相同的根目录验证，防止通过 `../` 或链接读取项目外文件。
- Markdown 渲染器采用明确的允许列表，并在交给界面前清理不受支持的内容。
- 远程资源请求在应用网络层和内容安全策略层同时阻止。

### 7.8 超大文件保护 `[REQ-TECH-LARGE-FILES]`

- 解析图片头部后，在完整解码前检查像素尺寸和格式有效性。
- 超过 1 亿像素的图片不进行完整 100% 解码，只生成有界尺寸的安全降采样预览。
- 超大图片仍显示文件名、路径、文件大小、像素尺寸、标记和错误/限制说明，并允许执行普通文件管理操作。
- 超过限制的图片不参与前后图片原图预载。
- 单个 Markdown/TXT 文件最多完整预览 10 MB；超过后只读取前 10 MB，并在截断位置显示说明。
- 超过 10 MB 的 Markdown/TXT 不进入全文索引，但文件名、路径、大小和修改时间仍可搜索和筛选。
- 解码器必须设置像素、内存和递归/嵌套保护，异常输入不得造成无限分配或阻塞主界面。

### 7.9 网络、隐私与诊断 `[REQ-TECH-PRIVACY]`

- Viewer 不要求登录、账户、许可证服务器或云端服务。
- 应用不检查在线更新，不在启动或运行时主动请求版本信息。
- 不采集使用分析、功能使用频率、项目路径、文件名、文本内容或图片数据。
- 不自动上传崩溃报告、诊断信息或日志。
- 诊断日志仅保存在本机，不包含文件正文、图片内容或不必要的完整绝对路径。
- 用户可主动导出诊断日志并自行提供给开发者；未经明确操作，日志不会离开本机。
- Markdown 中的外部链接只有在用户点击后，才交由系统默认浏览器处理；Viewer 自身不加载目标网页。
- 除上述用户主动打开链接外，首版应用按零网络依赖设计。

### 7.10 未来正式分发 `[REQ-TECH-DISTRIBUTION]`

- 正式产品名称为 **Viewer**。
- 未来进入正式分发阶段时，Viewer 仅面向 Apple Silicon，不提交 Mac App Store，并以可直接运行的 `.app` 交付；可封装为 DMG 便于安装。
- 未来正式分发必须使用 Developer ID 签名与公证；在不具备签名条件时，不将构建物视为正式分发，并需说明 Gatekeeper 的首次打开方式。
- 未来正式分发不建设自动更新通道，版本升级由用户手动替换应用完成。
- 应用升级不得覆盖项目目录中的 `.viewer` 元数据；遇到元数据版本变化时执行向前迁移并保留备份。
- 上述未来分发需求不属于 Viewer 0.1 当前开发阶段，也不构成当前发布门禁。

### 7.11 开源与第三方依赖治理 `[REQ-TECH-OPEN-SOURCE]`

- Viewer 源代码发布到公开 GitHub 仓库，并在仓库根目录提供明确的开源许可证。
- Viewer 采用成熟通用开源框架并独立实现产品代码，不复制其他完整应用的界面或实现。
- 正式进入构建的框架和库记录在 `THIRD_PARTY_NOTICES.md`；架构与产品行为的灵感来源记录在 `ACKNOWLEDGEMENTS.md`。
- Viewer 自身许可证必须在复制或修改任何第三方源码之前确定。
- 默认优先采用 MIT、Apache-2.0、BSD、ISC 和 CC0 等宽松许可证依赖。
- MPL、GPL、AGPL、FSL 和自定义许可证依赖必须单独评估，不得因仓库公开即可直接复制。
- 没有明确许可证的仓库视为保留全部权利，不复制其源码或资产。
- 所有直接依赖和源码复用记录进入 `THIRD_PARTY_NOTICES.md`，保留来源、版本、版权和许可证。
- Rust 与前端依赖都需要自动许可证扫描，并在发布前进行人工复核。
- 图标、字体、截图和示例图片等资产单独核验，代码许可证不自动覆盖仓库中的全部资产。
- 具体项目调研与候选依赖见 `docs/OPEN_SOURCE_RESEARCH.md`，技术来源矩阵见 `docs/TECHNICAL_FOUNDATIONS.md`。

## 8. 当前开发阶段

### 8.1 Viewer 0.1 定位

Viewer 0.1 是持续开发中的小型阶段性基线，不代表功能完成、内部发布或正式交付。M1、M2、M3 记录已经实现并验证的能力；后续功能按独立设计与计划继续开发，不设置 M4 或集中式最终验收阶段。

### 8.2 当前必须持续保持 `[REQ-SCOPE-MUST]`

- 已实现能力不得回归，数据安全、路径边界、权限最小化和本地优先约束持续生效。
- 新功能必须通过对应模块的自动化测试与持续门禁。
- 合成性能数据只用于回归比较，不代表真实素材最终验收。

### 8.3 当前明确不做 `[REQ-SCOPE-EXCLUSIONS]`

- 图片或文本编辑。
- AI 图片生成、提示词生成或模型调用。
- 云同步、多人协作、账户和在线服务。
- 同时打开多个项目或跨项目搜索。
- 插件系统和快捷键自定义。
- JPG、PNG、Markdown、TXT 之外的文件预览格式。
- Mac App Store 上架、自动更新和公开销售能力。
- Windows 版本的开发、打包与测试。

### 8.4 Windows 边界 `[REQ-SCOPE-WINDOWS]`

当前不开发 Windows 版本，也不为 Windows 进度牺牲当前 Mac 开发阶段的体验和推进速度。核心对象、元数据版本和业务接口避免无必要地绑定 macOS，但所有 Windows 兼容性均属于未来重新评估的工作，不计入当前开发阶段。

### 8.5 发布验收状态 `[REQ-RELEASE-ACCEPTANCE]`

当前开发阶段不设置发布验收。`.app`/DMG 交付、签名、公证、真实素材最终验收、干净机器安装和两小时稳定性验收均不属于 Viewer 0.1。
