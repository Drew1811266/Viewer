# 原生图片渲染器验收记录

## 范围与判定

本记录只覆盖普通单图预览与图片评审的原生 `wgpu`/Metal 渲染链路。网格、对比和视频沿用各自实现，不属于本次迁移范围。性能阈值与固定负载以 `image-renderer-baseline.json` 为唯一基线；任一硬指标超限、字段缺失或非有限数值，门禁均失败。

自动性能负载使用真正解码的 7680×4320 确定性图片、500 个混合标记以及连续 240 帧缩放/平移。验收程序运行真实 Tauri/AppKit/CAMetalLayer 窗口，输入经过生产原生 actor；帧指标来自 display-link 驱动的 surface 提交间隔，收据明确标为 `frame_timing: display_link_surface_submission`。这不是 GPU 完成时间、屏幕扫描时间或端到端输入延迟。GPU render-pass timestamp 独立异步回读，按 renderer 实例、素材 generation 与提交帧逐一匹配；硬件能力 `gpu_timing_support` 与成功样本 `gpu_sample_count` 分开记录，支持计时的设备缺少任一测量帧样本即不通过。GPU 时间不包含上传、排队或扫描显示时间。

正式门禁分别执行 `main` 和 `magnifier` 两个独立窗口测量，使用相同的 8K、500 标记、240 帧与数值阈值。后者开启 320×320 逻辑像素、2 倍圆形放大镜；收据中的 `magnifier_frame_samples` 来自实际编码帧，必须等于本场景全部测量帧数，普通场景必须为零。输出分别为 `receipt.json`、`receipt-magnifier.json`，任一场景不通过即整体失败；最终双场景通过证据见文末 2026-09-09 记录。

原生界面交互仍需实际执行 PRE-08、RVW-16～20、RVW-24、RVW-33～37 等适用场景。`test:native-acceptance` 与 `test:visual-acceptance` 仅验证验收脚本自身，不代替这些场景的实际界面验收。

评审保存指标来自真实 continuous-review authoring 写入，asset 与 region 两种场景各 30 次，并采用两种场景中较慢的分位数。materialization 单独执行但不混入用户点击“保存”后的前台延迟。

`VIEWER_IMAGE_RENDER_FIXTURE_ROOT` 可选择用于保存测量的本地素材工程，测量器复制选中素材到自己的临时工程，不写入用户工程。GPU 硬门禁始终使用输出目录内生成的固定 8K 图片，不要求用户工程里存在特定文件名，也不会向用户工程生成性能图片。

恢复策略为：一次可恢复 surface 故障留在原生引擎内重新配置并重试；连续两次可恢复故障升级为显式失败；校验错误或显存耗尽直接终止本次原生会话，不静默掩盖。输入边界必须零丢失，连续移动事件允许按显示帧合并。

### 单引擎边界

桌面生产组合根（真实 Tauri bridge）现在只创建 `NativeImageRenderer`；初始化或恢复失败保留原生诊断与重试状态，不切换 Web、Canvas、CPU 或其他轻量视口。仓库中的 `WebImageViewport`、旧手势 hook 和 DOM 标注实现仅供注入式浏览器/单元测试保持既有测试 oracle，生产 App 不注入这些实现；`scripts/repository-policy.test.mjs` 已加入防回退断言。网格、对比和视频继续沿用各自原有实现，不受本次单图渲染器收口影响。

因此，迁移期双引擎的生产切换开关已删除，稳定后的桌面单图预览与图片评审运行时为单一原生 wgpu/Metal 引擎；测试兼容层不属于产品运行时，也不构成用户可见兜底。
