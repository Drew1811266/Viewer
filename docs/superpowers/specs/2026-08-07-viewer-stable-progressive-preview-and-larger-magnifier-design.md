# Viewer 稳定渐进预览与放大镜档位修订设计

**日期：** 2026-08-07  
**状态：** 已批准  
**范围：** 单图预览首次显示、放大镜倍率、放大镜面积及对应设置迁移

**修订关系：** 本文覆盖
`2026-08-07-viewer-fit-relative-original-preview-revision-design.md` 中关于适窗代理是否允许放大、
放大镜 `1.5× / 2× / 3×` 档位、默认倍率和六种镜片尺寸的定义。适窗 `100%`、原图渐进替换、
触控板交互、Q 键与工具栏按钮的统一状态、指针旁放置及既有动画规则继续有效。

## 1. 背景与根因

当文件还没有原始尺寸元数据时，单图预览先用 `fit_preview` 返回的代理尺寸建立视口。当前适窗比例
被限制为不超过 `1`，因此一张约 `560 × 373` 的代理图在大舞台中只能按自身尺寸显示。约
0.5–1 秒后，`6582 × 4388` 一类原图表示到达，视口改用原图尺寸并缩小到舞台，于是用户看到明显的
“小图跳成大图”。

问题不在原图加载本身，而在适窗逻辑把“小尺寸代理不能放大”和“原图需要缩小”当成了两种不同的
呈现尺寸。修订必须保留快速代理的价值，同时让代理与原图共享同一屏幕边界。

## 2. 已批准的产品决策

1. 采用稳定尺寸的渐进预览：代理图先显示并立即填充适窗区域；原图到达后只提高像素质量，不改变
   屏幕位置、屏幕尺寸、相对倍率、旋转、平移或放大镜状态。
2. 不等待完整原图后才显示，也不增加双图交叉淡入层。
3. 放大镜倍率改为 `2× / 3× / 4×`，默认 `2×`。
4. 放大镜面积保持 `small / medium / large` 三个语义档位，固定尺寸改为：

   | 形状 | 小 | 中 | 大 |
   | --- | ---: | ---: | ---: |
   | 圆形 | 200 × 200 px | 280 × 280 px | 380 × 380 px |
   | 圆角矩形 | 230 × 150 px | 300 × 200 px | 420 × 280 px |

## 3. 稳定渐进预览

### 3.1 适窗比例

`fit` 模式必须把完整图像放入舞台约定的适窗内边距，无论当前表示的像素尺寸小于还是大于舞台。
适窗比例不再以 `1` 为上限：小代理可以被临时放大，大原图可以被缩小。工具栏仍把这一结果显示为
`100%`，因为百分比描述的是相对于适窗基准的倍率，不是源像素与 CSS 像素的一比一关系。

自由缩放继续使用 `fitScale × relativeZoom`，范围、锚点、旋转和平移边界规则不变。代理阶段的短暂
柔和只代表像素来源尚未升级，不得通过缩小图像来隐藏代理清晰度。

### 3.2 原子呈现几何

图像元素的 `width`、`height` 与 CSS transform 必须来自同一份已提交的视口几何。新的源尺寸只能先
进入视口测量，再与由该尺寸计算出的 transform 一起呈现；不得在一次渲染中把新 `width/height` 与
旧 transform 混用。

具体边界如下：

- 原始尺寸元数据存在时，从首次代理显示起就使用原始方向修正尺寸作为视口 source；
- 元数据缺失时，可以用代理尺寸作为临时 source，但因为适窗允许放大，代理仍立即占满目标边界；
- 原图尺寸到达时，URL 与 source 更新保持同一可见边界。相同比例的代理与原图替换前后屏幕宽高
  必须相等；只有源宽高比确实不同才允许按权威原图比例重新适窗；
- 图像切换、窗口变化和旋转继续通过同一视口状态机处理，不增加第二套布局状态。

实现时，源尺寸测量应在浏览器绘制前完成，图像属性应读取已经产生当前 transform 的视口 source，
从而避免代理 URL、原图 URL 和几何更新之间出现一帧不一致。

### 3.3 原图失败

原图超出安全预算或加载失败时，已经铺满适窗区域的代理保持当前屏幕尺寸，继续支持缩放、平移、旋转
和导航，并显示既有回退提示。失败不得让图像缩回代理的自然像素尺寸。取消、导航和卸载仍不显示错误。

## 4. 放大镜倍率与面积

### 4.1 倍率语义

公开倍率类型只接受 `2`、`3`、`4`。倍率仍表示相对于鼠标下当前可见主图的额外倍率，内部实际比例为：

`mainDisplayScale × selectedMagnification`

代理升级为原图后，放大镜继续使用当前原图采样；主图 `100%` 与 `200%` 下都必须分别体现选定的
`2× / 3× / 4×` 相对倍率。更新公开档位不得恢复独立的原始像素倍率语义。

### 4.2 面积与边界

六种批准尺寸是普通应用缩放下的固定 CSS 几何。镜片继续依据指针位置自动在左/右、上/下换边，并夹取
到预览舞台。舞台保持 `overflow: hidden`，因此极小窗口下镜片不能覆盖工具栏、导航或引发页面滚动；
不为极小窗口建立第四套隐式面积档位。

面积变化只改变镜片外壳和内部裁剪范围，不改变选定倍率、采样中心、指针间距、显隐动画或普通鼠标
箭头的可见性。

## 5. 设置版本与迁移

设置 schema 从 `3` 升到 `4`。schema 4 的默认值为：

- 缩略图密度：`standard`；
- 放大镜形状：`circle`；
- 放大镜倍率：`2`；
- 放大镜面积：`small`。

加载 schema 3 时：

- 保留缩略图密度、放大镜形状和面积；
- `1.5` 迁移为 `2`；
- `2` 和 `3` 保持不变；
- 下一次保存写出 schema 4；
- 无效、未知字段或损坏文件继续走完整默认值，不做部分猜测恢复。

schema 1 和 schema 2 的既有兼容规则保持不变。前端类型、设置控件、Tauri DTO、应用领域枚举和 JSON
存储必须使用同一组三个公开值，不允许任一层继续接受 `1.5`。

## 6. 验证策略

实施遵循测试驱动开发，至少覆盖：

1. 小于舞台的代理在 `fit` 模式也会填满适窗边界，仍显示 `100%`；
2. 元数据缺失时，代理 `560 × 373` 到原图 `6582 × 4388` 的相同比例替换前后可见宽高不变；
3. 替换不重置自由倍率、旋转、平移或活动放大镜；
4. 原图预算错误与普通错误保持已经铺满的代理尺寸；
5. 前端、DTO、领域和存储只接受 `2 / 3 / 4`，默认 `2`；
6. schema 3 的 `1.5 / 2 / 3` 按批准规则迁移，其他偏好得到保留；
7. 六种面积精确等于批准尺寸，正常边界自动翻转，极小舞台不产生页面溢出；
8. 放大镜在主图 `100%` 和 `200%` 下正确组合 `2× / 3× / 4×`；
9. 现有 UI、Rust、格式、类型、构建、安全、视觉和资源门禁无回归；
10. 最终启动一个最新开发版，由用户复查首次打开无尺寸跳切、三个倍率、三个面积和停止操作后的温度。

## 7. 不在本次范围

- 等待完整原图后才显示；
- 代理与原图双层交叉淡入；
- 任意数值倍率、滚轮调节镜片大小或自由拖拽镜片尺寸；
- 修改触控板灵敏度、放大镜位置、Q 键所有权或显隐动画参数；
- 绕过原图解码安全预算；
- 修改多图对比界面的显示逻辑。
